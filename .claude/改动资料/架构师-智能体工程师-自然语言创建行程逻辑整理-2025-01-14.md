# 自然语言创建行程逻辑整理

**完成日期**: 2025-01-14  
**整理角色**: 架构师、智能体工程师  
**目标**: 完整梳理自然语言创建行程的流程、决策点、技能选择和执行逻辑

---

## 📋 概述

自然语言创建行程功能允许用户通过自然语言描述（如"帮我规划带娃去东京5天的行程,预算2万"）创建新行程，系统会自动解析意图、选择技能、编排执行计划并生成行程。

**核心特点**：
- `trip_id` 为 `null`（创建新行程）
- 需要从消息中提取关键信息（目的地、日期、预算等）
- 需要构建 `world` 上下文（PhysicalRealityModel + HumanCapabilityModel + RouteDirection）
- 遵循严格的执行顺序（Gate → Plan → Verify → Repair）

## 🔄 完整流程

### 阶段 0：提前检查（Pre-Check）

**位置**: `ClaudeOrchestratorService.orchestrate()` - 步骤 0

**目的**: 在 LLM 调用之前识别创建新行程场景，避免不必要的 LLM 调用和超时

**检查逻辑**：
```typescript
// 1. 检测创建新行程场景
const isCreatingNewTrip = !request.trip_id || request.trip_id === '';

// 2. 检测规划类意图
const isPlanningIntent = 
  messageLower.includes('规划') ||
  messageLower.includes('计划') ||
  messageLower.includes('行程') ||
  messageLower.includes('安排');

// 3. 提取 countryCode
const countryCode = extractCountryCodeFromMessage(request.message);
```

**决策**：
- ✅ **如果 `countryCode` 存在**: 继续执行，记录日志
- ❌ **如果 `countryCode` 不存在**: 立即返回错误，要求用户提供目的地信息

**返回错误示例**：
```json
{
  "success": false,
  "result": {
    "needsUserConfirmation": true,
    "clarificationMessage": "无法完成行程规划，因为缺少必需的信息。\n\n缺失项：\n- 目的地国家或地区",
    "errorType": "MISSING_REQUIRED_PARAM",
    "missingParams": ["countryCode"],
    "solutions": [
      "在消息中明确指定目的地国家或地区（如：日本、东京、Japan）",
      "提供已保存的行程 ID，系统将自动获取国家代码"
    ]
  }
}
```

### 阶段 1：意图分析（Intent Analysis）

**位置**: `ClaudeOrchestratorService.analyzeIntent()`

**目的**: 使用 LLM 分析用户意图，确定任务类型和复杂度

**输入**:
- `request.message`: 用户自然语言输入
- `context`: Agent 上下文（包含 `tripId: null`）

**输出**: `IntentAnalysis`
```typescript
{
  intentType: 'simple_query' | 'complex_planning' | 'analysis' | 'decision' | 'mixed',
  complexity: 'simple' | 'medium' | 'complex',
  requiredCapabilities: string[],
  confidence: number,
  reasoning: string,
  keywords?: string[],
  entities?: Record<string, any>
}
```

**LLM Prompt**: `INTENT_ANALYSIS_PROMPT`

**关键点**:
- 对于创建新行程，`intentType` 通常为 `'complex_planning'`
- `complexity` 根据请求的详细程度判断
- `entities` 可能包含提取的目的地、日期、预算等信息

### 阶段 2：路由决策（Routing Decision）

**位置**: `ClaudeOrchestratorService.decideRouting()`

**目的**: 根据意图分析结果，选择执行路径（System 1 或 System 2）

**输入**: `IntentAnalysis`

**输出**: `RoutingDecision`
```typescript
{
  route: 'SYSTEM1_API' | 'SYSTEM1_RAG' | 'SYSTEM2_REASONING' | 'SYSTEM2_ANALYSIS' | 'SYSTEM2_WEBBROWSE',
  confidence: number,
  reasoning: string,
  budget: {
    max_seconds: number,
    max_steps: number,
    max_browser_steps: number
  }
}
```

**LLM Prompt**: `ROUTING_DECISION_PROMPT`

**决策逻辑**:
- 创建新行程通常路由到 `SYSTEM2_REASONING`（需要多步骤推理和技能调用）
- 如果路由到 `SYSTEM1_*`，直接返回，由 `AgentService` 处理

### 阶段 3：技能选择（Skills Selection）

**位置**: `ClaudeOrchestratorService.selectSkills()`

**目的**: 根据意图和路由决策，选择需要的 Skills

**输入**:
- `intentAnalysis`: 意图分析结果
- `routingDecision`: 路由决策
- `context`: Agent 上下文
- `llmProvider`: LLM 提供商

**输出**: `SkillsPlan`
```typescript
{
  selectedSkills: Array<{
    skillName: string,
    reason: string,
    priority: number,
    input: Record<string, any>,
    dependencies?: string[]
  }>,
  executionOrder: string[],
  dependencies: Record<string, string[]>
}
```

**LLM Prompt**: `SKILLS_SELECTION_PROMPT`

**核心原则**:
1. **Gate 优先**: 对于规划请求，必须包含 `plan.gate.runThreeGuardians` 或 `plan.gate.precheck`（在 `itinerary.generate` 之前）
2. **证据优先**: 优先选择能提供硬证据的 Skills（`transport.search`, `poi.search`, `opening_hours.get`, `dem.metrics`, `risk.check`）
3. **验证优先**: 生成行程后必须包含 `itinerary.verify` Skill
4. **修复能力**: 如果 Gate 结果为 `ADJUST_REQUIRED`，必须包含 `repair.apply` 和 `alternatives.generate` Skills

**典型技能选择（创建新行程）**:
```typescript
[
  {
    skillName: 'world.buildContext',
    reason: '创建新行程需要构建 world 上下文',
    priority: 1,
    input: { countryCode: 'JP' }
  },
  {
    skillName: 'routeDirection.pickForIntent',
    reason: '根据用户意图选择路线方向',
    priority: 2,
    input: { countryCode: 'JP', userIntentTags: [...] }
  },
  {
    skillName: 'plan.gate.runThreeGuardians',
    reason: '执行 Should-Exist Gate 评估',
    priority: 3,
    input: { world: '${world.buildContext.result.world}' }
  },
  {
    skillName: 'itinerary.generate',
    reason: '生成结构化行程草案',
    priority: 4,
    input: { world: '${world.buildContext.result.world}' }
  },
  {
    skillName: 'itinerary.verify',
    reason: '验证行程可行性',
    priority: 5,
    input: { itinerary: '${itinerary.generate.result.itinerary}' }
  }
]
```

### 阶段 3.5：自动添加 world.buildContext

**位置**: `ClaudeOrchestratorService.orchestrate()` - 步骤 4.5

**目的**: 对于创建新行程场景，如果选择了需要 `world`/`tripId` 的 skills，自动添加 `world.buildContext`

**检查逻辑**:
```typescript
if (isCreatingNewTrip) {
  const needsWorldOrTripId = skillsPlan.selectedSkills.some(skill => {
    const schema = skillMeta.inputSchema;
    const needsWorld = schema.dependencies?.some(dep => 
      dep.param === 'world' || dep.alternatives?.includes('world')
    );
    const needsTripId = schema.dependencies?.some(dep => 
      dep.param === 'tripId' || dep.alternatives?.includes('tripId')
    );
    return needsWorld || needsTripId;
  });
  
  if (needsWorldOrTripId) {
    const countryCode = extractCountryCodeFromMessage(request.message);
    if (!countryCode) {
      // 返回错误
    } else {
      // 自动添加 world.buildContext
      skillsPlan.selectedSkills.unshift({
        skillName: 'world.buildContext',
        input: { countryCode }
      });
    }
  }
}
```

### 阶段 4：提前验证（Early Validation）

**位置**: `ClaudeOrchestratorService.validateSkillsInputs()`

**目的**: 在 plan 编排之前验证 Skills 输入参数，避免浪费 LLM 调用成本

**验证逻辑**:
1. 遍历 `skillsPlan.selectedSkills`
2. 对每个 skill，使用 `SkillInputValidatorService.validate()` 验证
3. 支持两种验证方式：
   - **声明式验证**（优先）: 使用 `SkillMetadata.inputSchema`
   - **配置规则验证**（向后兼容）: 使用 `SKILL_VALIDATION_RULES`

**验证内容**:
- ✅ 必需参数检查
- ✅ 参数依赖关系检查（替代参数）
- ✅ 类型检查和范围检查
- ✅ 从 context/request/步骤结果提取参数

**如果验证失败**:
```typescript
return {
  success: false,
  result: {
    needsUserConfirmation: true,
    clarificationMessage: '...',
    errorType: 'MISSING_REQUIRED_PARAM',
    missingParams: [...],
    solutions: [...]
  }
};
```

### 阶段 5：执行计划编排（Execution Plan Planning）

**位置**: `ClaudeOrchestratorService.planExecution()`

**目的**: 使用 LLM 编排执行计划，确定 Skills 的执行顺序、依赖关系和并行执行策略

**输入**:
- `skillsPlan`: 选择的 Skills
- `routingDecision`: 路由决策
- `llmProvider`: LLM 提供商

**输出**: `ExecutionPlan`
```typescript
{
  steps: Array<{
    id: string,
    type: 'skill' | 'action' | 'parallel_group',
    skillName?: string,
    dependencies: string[],
    parallel: boolean,
    input?: Record<string, any>,
    fallback?: {
      onError: 'continue' | 'stop' | 'retry',
      retryCount?: number
    }
  }>,
  parallelGroups: string[][],
  fallbackStrategy: {
    onError: 'continue' | 'stop',
    retryCount: number
  }
}
```

**LLM Prompt**: `EXECUTION_PLANNING_PROMPT`

**强制顺序**:
1. **INTAKE**: 解析请求 & 缺口识别（Planner Agent）
2. **RESEARCH**: 调用 skills 获取硬数据（`transport.search`, `poi.search`, `opening_hours.get`, `dem.metrics`, `risk.check`）
3. **GATE_EVAL**: 执行 Should-Exist Gate 决策（Gatekeeper Agent，**必须在 PLAN_GEN 之前**）
4. **PLAN_GEN**: 生成结构化行程草案（Planner Agent，仅在 Gate 结果为 `ALLOW` 或 `ADJUST_REQUIRED` 时执行）
5. **VERIFY**: 验证开放时间冲突/换乘 buffer/可达性/疲劳阈值（`itinerary.verify`）
6. **REPAIR**: 替换POI/改路线/加buffer/换交通/降级（仅在需要时执行，LocalInsight Agent + `repair.apply`）
7. **NARRATE**: 产出用户可读解释（Narrator Agent，**不得改硬字段**）

**编排原则**:
1. **依赖关系**: 确保依赖的 Skills 先执行
2. **并行执行**: 无依赖的 Skills 可以并行执行，提高效率
3. **错误处理**: 为每个步骤设计降级策略
4. **成本优化**: 优先执行低成本、高价值的 Skills

**典型执行计划（创建新行程）**:
```json
{
  "steps": [
    {
      "id": "step1",
      "type": "skill",
      "skillName": "world.buildContext",
      "dependencies": [],
      "parallel": false,
      "input": {
        "countryCode": "JP"
      }
    },
    {
      "id": "step2",
      "type": "skill",
      "skillName": "routeDirection.pickForIntent",
      "dependencies": ["step1"],
      "parallel": false,
      "input": {
        "countryCode": "JP",
        "userIntentTags": ["family", "relaxed"]
      }
    },
    {
      "id": "step3",
      "type": "skill",
      "skillName": "plan.gate.runThreeGuardians",
      "dependencies": ["step1", "step2"],
      "parallel": false,
      "input": {
        "world": "${step1.result.world}"
      }
    },
    {
      "id": "step4",
      "type": "skill",
      "skillName": "itinerary.generate",
      "dependencies": ["step3"],
      "parallel": false,
      "input": {
        "world": "${step1.result.world}",
        "routeDirection": "${step2.result.routeDirection}"
      },
      "fallback": {
        "onError": "continue",
        "retryCount": 1
      }
    },
    {
      "id": "step5",
      "type": "skill",
      "skillName": "itinerary.verify",
      "dependencies": ["step4"],
      "parallel": false,
      "input": {
        "itinerary": "${step4.result.itinerary}"

    "onError": "continue",

  }
}
```

### 阶段 6：执行计划（Execute Plan）

**位置**: `ClaudeOrchestratorService.executePlan()`

**目的**: 按计划顺序执行 Skills，收集结果

**执行逻辑**:
```typescript
for (const step of plan.steps) {
  // 1. 准备输入参数（可以使用前面步骤的结果）
  const input = prepareSkillInput(step, results, context, request);
  
  // 2. 执行 Skill
  const skill = skillsRegistry.getSkill(step.skillName);
  const result = await skill.execute(input);
  
  // 3. 保存结果
  results[step.id] = result;
  
  // 4. 记录执行日志
  stepsExecuted.push({
    stepId: step.id,
    skillName: step.skillName,
    success: true,
    result,
    duration: Date.now() - stepStartTime
  });
}
```

**关键 Skills 执行流程**:

#### 6.1 world.buildContext

**输入**:
```typescript
{
  countryCode: 'JP',  // 从消息中提取
  season?: number,    // 从消息中提取或使用默认值
  duration?: number,  // 从消息中提取
  partyProfile?: {    // 从消息中提取或使用默认值
    mobilityProfile?: string,
    riskTolerance?: 'low' | 'medium' | 'high',
    fitness?: 'low' | 'medium' | 'high',
    pace?: 'relaxed' | 'moderate' | 'intense'
  }
}
```

5. 组装 `WorldModelContext`

**输出**:

```typescript
{
  world: WorldModelContext,  // 包含 PhysicalRealityModel + HumanCapabilityModel + RouteDirection

    demGaps?: string[],
    humanProfileIncomplete?: boolean,
    routeDirectionMissing?: boolean,
    physicalRealityIncomplete?: boolean
  }

```

#### 6.2 routeDirection.pickForIntent

**输入**:

## 🔍 关键决策点

### 决策点 1：是否创建新行程？

**判断条件**:
```typescript
const isCreatingNewTrip = !request.trip_id || request.trip_id === '';
```

**影响**:
- ✅ 如果是创建新行程，允许 `trip_id` 为 `null`
- ✅ 需要从消息中提取关键信息（`countryCode`, `season`, `duration` 等）
- ✅ 需要构建 `world` 上下文（通过 `world.buildContext`）

### 决策点 2：能否提取 countryCode？

**判断条件**:
```typescript
const countryCode = extractCountryCodeFromMessage(request.message);
```

**提取逻辑**:
- 支持国家名映射（"日本" → "JP", "Iceland" → "IS"）
- 支持城市名映射（"东京" → "JP", "Reykjavik" → "IS"）
- 大小写不敏感

**影响**:
- ❌ 如果无法提取，立即返回错误，要求用户提供目的地信息
- ✅ 如果能够提取，继续执行，自动添加 `world.buildContext` 到 `skillsPlan`

### 决策点 3：是否需要 world 上下文？

**判断条件**:
```typescript
const needsWorldOrTripId = skillsPlan.selectedSkills.some(skill => {
  const schema = skillMeta.inputSchema;
  const needsWorld = schema.dependencies?.some(dep => 
    dep.param === 'world' || dep.alternatives?.includes('world')
  );
  const needsTripId = schema.dependencies?.some(dep => 
    dep.param === 'tripId' || dep.alternatives?.includes('tripId')
  );
  return needsWorld || needsTripId;
});
```

**影响**:
- ✅ 如果需要，自动添加 `world.buildContext` 到 `skillsPlan`
- ✅ 确保后续步骤能够获取 `world` 上下文

### 决策点 4：Gate 评估结果？

**Gate 结果**:
- `ALLOW`: 允许生成行程，继续执行 `itinerary.generate`
- `ADJUST_REQUIRED`: 需要调整，执行 `repair.apply` 后继续
- `REJECT`: 拒绝，返回错误，建议用户修改需求

## 📊 数据流

### 输入数据流

```
用户自然语言输入
  ↓
提取关键信息（countryCode, season, duration, budget, preferences）
  ↓
构建 AgentContext { tripId: null, userId, requestId, ... }
```

```
world.buildContext 结果
  ↓
WorldModelContext { physicalReality, humanCapability, routeDirection }
  ↓
传递给后续 Skills（plan.gate.runThreeGuardians, itinerary.generate, ...）
```

### 输出数据流

```
Skills 执行结果
  ↓
组装 OrchestrationResult
  ↓
返回给 AgentService
  ↓
转换为 RouteAndRunResponseDto
  ↓
返回给前端
```

## 🛠️ 关键技能（Skills）

### world.buildContext

**用途**: 构建完整的世界模型上下文

**输入**:
- `countryCode`（必需，从消息中提取）
- `season`（可选，从消息中提取或使用默认值）
- `duration`（可选，从消息中提取）
- `partyProfile`（可选，从消息中提取或使用默认值）

**输出**:
- `world`: `WorldModelContext`（包含 PhysicalRealityModel + HumanCapabilityModel + RouteDirection）
- `missingPieces`: 缺失的数据片段

**依赖**: 无（第一个执行的 Skill）

**被依赖**: `plan.gate.runThreeGuardians`, `itinerary.generate`, `decision.runThreeGuardians` 等

### routeDirection.pickForIntent

**用途**: 根据用户意图选择路线方向

**输入**:
- `countryCode`（必需）
- `userIntentTags`（必需，从消息中提取）
- `season`（可选）

**输出**:
- `routeDirectionId`: 选中的路线方向 ID
- `routeDirection`: 路线方向对象
- `reasoning`: 选择理由
- `alternatives`: 备选路线方向

**依赖**: `world.buildContext`（可选，用于获取 RouteDirection 列表）

### plan.gate.runThreeGuardians

**用途**: 执行 Should-Exist Gate 评估（硬门控+软评分，三人格完整评审）

**输入**:
- `world`（必需，从 `world.buildContext` 的结果中提取）
- `routeDirection`（可选，从 `routeDirection.pickForIntent` 的结果中提取）

**输出**:
- `gateResult`: `'ALLOW' | 'ADJUST_REQUIRED' | 'REJECT'`
- `violations`: 违规项列表
- `requiredAdjustments`: 需要的调整
- `confidence`: 置信度

**依赖**: `world.buildContext`, `routeDirection.pickForIntent`

**被依赖**: `itinerary.generate`（仅在 Gate 结果为 `ALLOW` 或 `ADJUST_REQUIRED` 时执行）

### itinerary.generate

**用途**: 生成结构化行程草案

**输入**:
- `world`（必需，从 `world.buildContext` 的结果中提取）
- `routeDirection`（可选，从 `routeDirection.pickForIntent` 的结果中提取）
- `constraints`（可选，从消息中提取：预算、日期等）
- `preferences`（可选，从消息中提取）

**输出**:
- `itinerary`: `Itinerary`（包含 days, items, timeline 等）
- `reasoning`: 生成理由
- `alternatives`: 备选行程（可选）

**依赖**: `plan.gate.runThreeGuardians`（必须在 Gate 之后执行）

**被依赖**: `itinerary.verify`

### itinerary.verify

**用途**: 验证行程的可行性

**输入**:
- `itinerary`（必需，从 `itinerary.generate` 的结果中提取）
- `research_data`（可选）

**输出**:
- `valid`: 是否有效
- `issues`: 问题列表
- `fixes`: 修复建议（可选）

**依赖**: `itinerary.generate`

**被依赖**: `repair.apply`（如果发现问题）

### repair.apply

**用途**: 应用修复方案到行程

**输入**:
- `itinerary`（必需，从 `itinerary.generate` 的结果中提取）
- `adjustments`（必需，从 `itinerary.verify` 的结果中提取）

**输出**:
- `repairedItinerary`: 修复后的行程
- `changes`: 变更列表

**依赖**: `itinerary.generate`, `itinerary.verify`

## 🚨 错误处理

### 错误类型

1. **MISSING_REQUIRED_PARAM**: 缺少必需参数
   - **处理**: 返回澄清消息，要求用户提供信息
   - **示例**: 缺少 `countryCode`

2. **TIMEOUT**: 请求超时
   - **处理**: 返回超时错误，建议用户重试
   - **示例**: LLM 调用超时或技能执行超时

3. **INTERNAL_ERROR**: 内部错误
   - **处理**: 返回错误消息，记录日志
   - **示例**: 数据库查询失败、服务不可用

### 错误处理策略

**Fallback 策略**:
- `continue`: 继续执行后续步骤
- `stop`: 停止执行
- `retry`: 重试（最多 `retryCount` 次）

**错误恢复**:
- 如果某个 Skill 失败，根据 `fallback.onError` 策略处理
- 如果关键 Skill 失败（如 `world.buildContext`），返回错误

## 🔧 参数提取机制

### 从消息中提取 countryCode

**位置**: `ClaudeOrchestratorService.extractCountryCodeFromMessage()`

**提取逻辑**:
```typescript
const countryMap: Record<string, string> = {
  // 国家名
  '冰岛': 'IS', 'Iceland': 'IS', 'iceland': 'IS',
  '中国': 'CN', 'China': 'CN', 'china': 'CN',
  '日本': 'JP', 'Japan': 'JP', 'japan': 'JP',
  '美国': 'US', 'United States': 'US', 'USA': 'US',
  
  // 城市名映射到国家
  '东京': 'JP', 'Tokyo': 'JP', 'tokyo': 'JP',
  '大阪': 'JP', 'Osaka': 'JP',
  '京都': 'JP', 'Kyoto': 'JP',
  '北京': 'CN', 'Beijing': 'CN',
  '上海': 'CN', 'Shanghai': 'CN',
  '雷克雅未克': 'IS', 'Reykjavik': 'IS', 'reykjavik': 'IS',
};

const lowerMessage = message.toLowerCase();
for (const [key, code] of Object.entries(countryMap)) {
  if (lowerMessage.includes(key.toLowerCase())) {
    return code;
  }
}
```

**特点**:
- 大小写不敏感
- 支持国家名和城市名映射
- 简单字符串匹配（可扩展为更智能的 NLP 提取）

### 从消息中提取月份

**位置**: `ClaudeOrchestratorService.extractMonthFromMessage()`

**提取逻辑**:
- 支持中文月份关键词（"一月"、"1月"）
- 支持英文月份关键词（"January"、"Jan"）
- 支持日期格式（YYYY-MM-DD）

### 从步骤结果中提取参数

**位置**: `SkillInputValidatorService.extractFromStepResult()`

**提取逻辑**:
```typescript
// 1. 尝试直接使用 stepId 查找结果
let result = stepResults[stepId];

// 2. 如果找不到，尝试通过 skillName 查找
if (!result && planSteps) {
  const step = planSteps.find(s => s.id === stepId || s.skillName === stepId);
  if (step) {
    result = stepResults[step.id];
  }
}

// 3. 如果指定了路径，从结果中提取（支持嵌套路径）
if (path) {
  return this.getNestedValue(result, path);  // 支持 'result.itinerary' 这样的路径
}
```

**示例**:
```typescript
// 从 itinerary.generate 的结果中提取 itinerary
extractors: {
  itinerary: {
    type: 'step',
    stepId: 'itinerary.generate',
    path: 'result.itinerary',  // 支持嵌套路径
  }
}
```

## 🎯 优化点

### 已实现的优化

1. ✅ **提前检查**: 在 LLM 调用之前识别创建新行程场景，避免不必要的 LLM 调用

   - 并行执行无依赖的 Skills
