## 📋 inputSchema 使用指南

### 必需参数

使用 `required` 数组定义必需参数：

```typescript
inputSchema: {
  required: ['param1', 'param2'],
}
```

### 参数依赖关系

使用 `dependencies` 定义参数之间的依赖和替代关系：

```typescript
inputSchema: {
  dependencies: [
    { param: 'world', alternatives: ['tripId'] },
    { param: 'tripId', alternatives: ['world'] },
  ],
}
```

**说明**：
- `param`: 参数名
- `alternatives`: 替代参数列表（如果这些参数存在，该参数可选）

### 参数提取器

使用 `extractors` 定义如何从 context/request 中提取参数：

```typescript
inputSchema: {
  extractors: {
    tripId: 'tripId',
    countryCode: 'countryCode',
  },
}
```

**支持的提取器名称**：
- `tripId`: 从 context.tripId 或 request.trip_id 中提取
- `countryCode`: 从 request.message 中提取国家代码

## ✅ 实施效果

### 优势

1. **声明式验证**：验证规则定义在 skill 的 metadata 中，与 skill 定义在一起
2. **类型安全**：TypeScript 接口提供类型检查
3. **易于维护**：验证规则与 skill 代码在一起，便于理解和维护
4. **自动验证**：`SkillInputValidatorService` 会自动读取 `inputSchema` 并执行验证

### 迁移路径

1. **新 skill**：直接使用 `inputSchema` 定义验证规则
2. **现有 skill**：逐步从 `SKILL_VALIDATION_RULES` 配置迁移到 `inputSchema`
3. **向后兼容**：如果 skill 没有 `inputSchema`，会降级到配置规则
