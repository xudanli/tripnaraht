# 改动资料文件夹规范说明

**创建日期**: 2025-01-14  
**创建角色**: 系统管理员  
**规范级别**: 🔴 必须遵守

---

## 规范概述

从 2025-01-14 起，**所有内部角色（如产品经理、架构师、工程师等）输出的方案、总结报告、分析文档等改动资料，统一存储在 `.claude/改动资料/` 文件夹中**。

---

## 适用范围

### ✅ 应存储在此文件夹的文档

1. **产品经理输出**
   - 产品方案文档
   - 需求分析报告
   - 功能设计文档
   - 产品总结报告

2. **架构师输出**
   - 架构设计方案
   - 技术选型报告
   - 架构改进建议
   - 技术分析报告

3. **工程师输出**
   - 技术分析报告
   - 问题诊断报告
   - 实施总结文档
   - 代码改进方案

4. **其他内部文档**
   - 多角色协作总结
   - 项目进度报告
   - 技术决策记录

### ❌ 不应存储在此文件夹的文档

- 系统运行时使用的 prompt 文件（应存储在 `prompts/` 目录）
- 角色定义文件（应存储在 `.claude/roles/` 目录）
- 系统技能定义（应存储在 `prompts/skills/` 目录）
- 用户文档（应存储在 `docs/` 目录）
- 代码实现文件（应存储在 `src/` 目录）

---

## 命名规范

### 格式

```
[角色]-[类型]-[主题]-[日期].md
```

### 示例

```
产品经理-方案-前端API变更-2025-01-14.md
架构师-分析-依赖注入问题-2025-01-14.md
智能体工程师-总结-TransportSkill修复-2025-01-14.md
多角色-协作-角色定义完成-2025-01-14.md
```

### 说明

- **角色**：产品经理、架构师、智能体工程师、数据库工程师等
- **类型**：方案、分析、总结、报告、建议等
- **主题**：简短描述文档主题（使用中文或英文）
- **日期**：格式为 `YYYY-MM-DD`

## 文件夹结构（可选）

可根据需要创建子文件夹进行分类：

```
.claude/改动资料/
├── README.md                    # 说明文件
├── 产品经理/                     # 产品经理相关文档
│   ├── 方案/
│   ├── 需求分析/
│   └── 总结报告/
├── 架构师/                      # 架构师相关文档
│   ├── 设计方案/
│   ├── 技术分析/
│   └── 改进建议/
├── 工程师/                      # 工程师相关文档
│   ├── 技术分析/
│   ├── 问题诊断/
│   └── 实施总结/
└── 协作/                        # 多角色协作文档
    ├── 协作总结/
    └── 决策记录/
```

**注意**：文件夹结构可根据实际需要调整，但应保持清晰和有序。
