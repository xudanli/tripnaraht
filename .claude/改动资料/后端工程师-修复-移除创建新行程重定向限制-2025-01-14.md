# 移除创建新行程重定向限制 - 修复说明

**修复日期**: 2025-01-14  
**修复角色**: 后端工程师  
**问题**: 从"创建新行程"页面发起的规划请求被错误地重定向到规划工作台

---

## 🔴 问题描述

### 问题现象

从"创建新行程"页面（自然语言输入）发起的请求，例如：
- 用户输入："帮我规划带娃去东京5天的行程,预算2万"
- 请求被检测为规划请求
- 返回 `REDIRECT_REQUIRED` 状态，`redirect_reason: "PLANNING_REQUEST_DETECTED"`
- 用户被重定向到规划工作台

### 问题原因

1. **原有逻辑**：只要检测到规划请求，就重定向到规划工作台
2. **问题**：创建新行程时 `trip_id` 为 `null`，且消息包含规划关键词，被误判为需要重定向
3. **影响**：无法通过 `route_and_run` 接口创建新行程

---

## ✅ 修复方案

### 修复逻辑

**核心原则**：如果 `trip_id` 为空且是规划请求，说明是创建新行程，不应该重定向。

**修复后的逻辑**：
1. 判断是否是创建新行程：`trip_id` 为空 + 是规划请求
2. 判断是否从 dashboard 发起：`entry_point === 'dashboard'`
3. 只有在**非创建新行程**且**非 dashboard 入口**时，才重定向到规划工作台

### 修复代码

```typescript
// 0. 检查是否是规划请求（需要拦截，重定向到规划工作台）
// 注意：创建新行程时 trip_id 为 null 是正常的，应该允许通过（自然语言创建行程功能）
// 如果 trip_id 为空且是规划请求，说明是创建新行程，不应该重定向
const isFromDashboard = request.options?.entry_point === 'dashboard';
const isCreatingNewTrip = (!request.trip_id || request.trip_id === '') && this.isPlanningRequest(request);

// 只有在非创建新行程场景下才重定向到规划工作台
// 如果是从 dashboard 创建新行程，或者 trip_id 为空且是规划请求，都允许通过
if (this.isPlanningRequest(request) && !isCreatingNewTrip && !isFromDashboard) {
  this.logger.debug(`[AgentService] 检测到规划请求，重定向到规划工作台: request_id=${request.request_id}, message=${request.message.substring(0, 50)}...`);
  return this.createRedirectToPlanningWorkbenchResponse(request, startTime);
}

// 0.1 验证 trip_id
// 注意：创建新行程时 trip_id 为 null 是正常的（通过自然语言创建行程功能）
// 只有在已有行程的操作（查询、修改等）时才需要 trip_id
// 如果是从 dashboard 创建新行程，或者 trip_id 为空且是规划请求，允许 trip_id 为 null
if (!isCreatingNewTrip && !isFromDashboard && (!request.trip_id || request.trip_id === '')) {
  // 只有在非创建新行程场景下才要求 trip_id
  this.logger.warn(`[AgentService] 缺少 trip_id（非创建新行程场景）: request_id=${request.request_id}, message=${request.message.substring(0, 50)}...`);
  return this.createMissingTripIdErrorResponse(request, startTime);
}
```

## ✅ 修复后的行为

### 场景 1：从 Dashboard 创建新行程（有 entry_point）

**请求**：
```json
{
  "request_id": "req-001",
  "user_id": "user-123",
  "trip_id": null,
  "message": "帮我规划带娃去东京5天的行程,预算2万",
  "options": {
    "entry_point": "dashboard"
  }
}
```

**行为**：
- ✅ `isFromDashboard = true`
- ✅ `isCreatingNewTrip = true`（trip_id 为空 + 是规划请求）
- ✅ 不重定向，继续执行 `route_and_run` 流程
- ✅ 如果信息不足，返回澄清问题

### 场景 2：从 Dashboard 创建新行程（无 entry_point，但 trip_id 为空 + 规划请求）

**请求**：
```json
{
  "request_id": "req-002",
  "user_id": "user-123",
  "trip_id": null,
  "message": "帮我规划带娃去东京5天的行程,预算2万"
}
```

**行为**：
- ✅ `isFromDashboard = false`（未传递 entry_point）
- ✅ `isCreatingNewTrip = true`（trip_id 为空 + 是规划请求）
- ✅ 不重定向，继续执行 `route_and_run` 流程
- ✅ **关键改进**：即使前端没有传递 `entry_point`，也能正确识别为创建新行程

### 场景 3：已有行程的操作

**请求**：
```json
{
  "request_id": "req-003",
  "user_id": "user-123",
  "trip_id": "trip-456",
  "message": "查询行程状态"
}
```

**行为**：
- ✅ `isCreatingNewTrip = false`（有 trip_id）
- ✅ 继续执行 `route_and_run` 流程

### 场景 4：其他入口的规划请求（需要重定向）

**请求**：
```json
{
  "request_id": "req-004",
  "user_id": "user-123",
  "trip_id": "trip-456",
  "message": "帮我规划新行程",
  "options": {
    "entry_point": "trip_detail_page"
  }
}
```

**行为**：
- ✅ `isCreatingNewTrip = false`（有 trip_id，不是创建新行程）
- ✅ `isFromDashboard = false`（不是 dashboard 入口）
- ✅ 重定向到规划工作台

---

## 📋 关键改进点

### 1. 更宽松的创建新行程判断

**之前**：只有 `entry_point === 'dashboard'` 时才允许创建新行程

**现在**：如果 `trip_id` 为空且是规划请求，就认为是创建新行程，无论是否有 `entry_point`

### 2. 双重保护

- **保护 1**：如果 `trip_id` 为空且是规划请求，不重定向
- **保护 2**：如果 `entry_point === 'dashboard'`，不重定向

### 3. 向后兼容

- 已有行程的操作（有 `trip_id`）不受影响
- 其他入口的规划请求仍然会重定向
