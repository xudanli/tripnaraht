✅ **5. 实现生成逻辑**
- 在 `ClaudeOrchestratorService.executeIntakeStep()` 中：
  - 检测 HARD 缺口
  - 调用 `generateClarificationQuestions()` 生成结构化澄清问题
  - 填充到 `state.clarification_questions`

✅ **6. 实现结果构建方法**
- 更新了 `buildSuccessResult()`：如果有澄清问题，返回 `success: false` 并填充 `clarificationQuestions`
- 更新了 `buildBlockedResult()`：如果有澄清问题，也填充到结果中
- 新增了 `buildClarificationResult()`：专门用于构建澄清结果
- 新增了 `formatClarificationMessage()`：将结构化问题转换为简单字符串（向后兼容）

✅ **7. 实现状态机流程优化**
- 在 `orchestrateWithStateMachine()` 中：
  - 检测到 HARD 缺口且有澄清问题时，提前返回澄清结果
  - 不继续执行后续步骤（RESEARCH、GATE_EVAL 等）

✅ **8. 实现降级模式支持**
- 在 `executeIntakeStep()` 中：
  - 当 PlannerAgent 不可用时，使用 `identifyGapsFromRequest()` 识别缺口
  - 生成结构化澄清问题

✅ **9. 更新 Agent Service**
- 在 `agent.service.ts` 的 `routeAndRunWithClaudeStateMachine()` 中：
  - 将 `clarificationQuestions` 填充到响应中

## 🔧 技术实现细节

### 1. 数据结构定义

**文件**: `src/agent/interfaces/clarification.interface.ts`

```typescript
export type ClarificationQuestionType = 
  | 'text'           // 文本输入
  | 'single_choice'  // 单选
  | 'multi_choice'   // 多选
  | 'date'           // 日期选择
  | 'number';        // 数字输入

export interface ClarificationValidation {
  /** 最小值（用于 number 和 date，date 类型使用时间戳） */
  min?: number;
  /** 最大值（用于 number 和 date，date 类型使用时间戳） */
  max?: number;
  /** 正则表达式（用于 text） */
  pattern?: string;
}

export interface ClarificationQuestion {
  id: string;
  question: string;
  type: ClarificationQuestionType;
  options?: string[];
  required: boolean;
  placeholder?: string;
  hint?: string;
  default?: string | string[];
  validation?: ClarificationValidation;
}
```

**关键点**：
- ✅ 日期验证规则使用时间戳（`number`），符合前端评审意见
- ✅ 类型定义清晰，符合前端需求

### 2. 生成逻辑实现

**文件**: `src/agent/services/claude-orchestrator.service.ts`

**方法**: `generateClarificationQuestions()`

**逻辑**：
- 根据缺口类型（`MISSING_DESTINATION`、`MISSING_DATES`、`MISSING_CONSTRAINTS`、`MISSING_PREFERENCES`）生成对应的问题
- 支持多种问题类型（text、single_choice、multi_choice、date、number）
- 包含验证规则（min/max 用于 number 和 date，pattern 用于 text）

**示例生成的问题**：
- `MISSING_DESTINATION` → text 类型问题
- `MISSING_DATES` → date 类型问题（开始日期 + 结束日期）
- `MISSING_CONSTRAINTS` → single_choice（人数）+ number（预算）
- `MISSING_PREFERENCES` → multi_choice（兴趣）+ single_choice（节奏）

### 3. 状态机流程优化

**关键改进**：
- 在 `orchestrateWithStateMachine()` 中，检测到 HARD 缺口且有澄清问题时，提前返回
- 不继续执行 RESEARCH、GATE_EVAL 等步骤，节省资源

**代码位置**：
```typescript
// 步骤 1: INTAKE - 解析请求 & 缺口识别
await this.executeIntakeStep(request, context, state, llmProvider);

// 如果有 HARD 缺口，提前返回澄清结果
const hasHardGaps = state.gaps && state.gaps.some(g => g.severity === 'HARD');
if (hasHardGaps && state.clarification_questions && state.clarification_questions.length > 0) {
  return this.buildClarificationResult(state, startTime);
}
```

### 4. 向后兼容实现

**策略**：
- 同时支持 `clarificationMessage`（简单字符串）和 `clarificationQuestions`（结构化数组）
- 如果生成了结构化问题，自动生成简单字符串格式（通过 `formatClarificationMessage()`）
- 前端可以根据需要选择使用哪种格式
