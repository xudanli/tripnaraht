## 🔍 问题分析

### 智能体工程师分析

**依赖链分析**：
```
StrategyOrchestratorService
  ├─ AbuStrategy ✅ (已提供)
  ├─ DrDreStrategy ✅ (已提供)
  ├─ NeptuneStrategy ✅ (已提供)
  ├─ DecisionLogStorageService ✅ (已提供)
  ├─ ContextEngineerService ⚠️ (@Optional, 来自 ContextEngineModule)
  └─ SkillsRegistryService ⚠️ (@Optional, 来自 SkillsModule)
```

**关键发现**：
- `ContextEngineerService` 和 `SkillsRegistryService` 都是 `@Optional()` 的
- 但 `DecisionModule` 中，`ContextEngineModule` 和 `SkillsModule` 是条件导入：
  - `enableContextEngineModule = process.env.ENABLE_CONTEXT_ENGINE_MODULE === 'true'`（默认 false）
  - `enableSkillsModule = process.env.ENABLE_SKILLS_MODULE === 'true'`（默认 false）

**可能的问题**：
1. 即使依赖是 `@Optional()`，如果模块未导入，NestJS 可能仍会尝试解析
2. 或者，`AbuStrategy`、`DrDreStrategy`、`NeptuneStrategy` 的初始化可能有问题

### 架构师分析

**模块依赖关系**：
```
AgentModule
  └─ DecisionModule
      ├─ ContextEngineModule (条件导入，默认 false)
      ├─ SkillsModule (条件导入，默认 false)
      └─ StrategyOrchestratorService
          ├─ AbuStrategy
          ├─ DrDreStrategy
          ├─ NeptuneStrategy
          └─ (可选依赖)
```

**阻塞可能的原因**：
1. **循环依赖**：虽然使用了 `forwardRef`，但可能仍有隐藏的循环依赖
2. **初始化顺序**：某个策略服务的初始化可能阻塞
3. **可选依赖解析**：即使标记为 `@Optional()`，NestJS 可能仍会尝试解析

**建议**：
- 使用懒加载（`ModuleRef.get()`）获取可选依赖
- 或者，确保相关模块被正确导入

### 后端工程师分析

**当前配置**：
- `DecisionModule` 中，`ContextEngineModule` 和 `SkillsModule` 默认未导入
- `StrategyOrchestratorService` 依赖这两个模块的服务（但标记为 `@Optional()`）

**问题**：
- 即使依赖是 `@Optional()`，如果模块未导入，NestJS 在解析依赖时可能会阻塞
- 或者，`AbuStrategy`、`DrDreStrategy`、`NeptuneStrategy` 的某个依赖链有问题

**解决方案**：
1. **方案 1（推荐）**：使用懒加载获取可选依赖
2. **方案 2**：确保 `ContextEngineModule` 和 `SkillsModule` 被导入（如果它们可用）
3. **方案 3**：暂时回退，使用降级处理

## ✅ 修复方案

### 方案 1：使用懒加载（推荐）

**原理**：不在构造函数中注入可选依赖，而是在需要时通过 `ModuleRef` 获取。

**优点**：
- 避免启动时的依赖解析阻塞
- 保持功能完整性
- 不影响其他服务

**实施**：
```typescript
@Injectable()
export class StrategyOrchestratorService {
  private contextEngineer?: ContextEngineerService;
  private skillsRegistry?: SkillsRegistryService;

  constructor(
    private readonly abu: AbuStrategy,
    private readonly dre: DrDreStrategy,
    private readonly nep: NeptuneStrategy,
    private readonly logStorage: DecisionLogStorageService,
    private readonly moduleRef: ModuleRef, // 添加 ModuleRef
  ) {}

  // 懒加载获取 ContextEngineerService
  private getContextEngineer(): ContextEngineerService | undefined {
    if (!this.contextEngineer) {
      try {
        this.contextEngineer = this.moduleRef.get(ContextEngineerService, { strict: false });
      } catch {
        // 服务不可用，返回 undefined
      }
    }
    return this.contextEngineer;
  }

  // 懒加载获取 SkillsRegistryService
  private getSkillsRegistry(): SkillsRegistryService | undefined {
    if (!this.skillsRegistry) {
      try {
        this.skillsRegistry = this.moduleRef.get(SkillsRegistryService, { strict: false });
      } catch {
        // 服务不可用，返回 undefined
      }
    }
    return this.skillsRegistry;
  }
}
```

### 方案 2：确保模块导入

**原理**：如果 `ContextEngineModule` 和 `SkillsModule` 在 `AgentModule` 中已导入，确保 `DecisionModule` 也能访问它们。

**实施**：
- 检查 `AgentModule` 是否导入了 `ContextEngineModule` 和 `SkillsModule`
- 如果已导入，确保 `DecisionModule` 也能访问（通过全局模块或重新导入）
