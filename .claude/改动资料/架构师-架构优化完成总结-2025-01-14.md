### 2. 扩展 SkillMetadata 接口，支持 inputSchema

**文件**: `src/skills/interfaces/skill.interface.ts`

**新增接口**：
```typescript
export interface SkillInputSchema {
  /** 必需参数列表 */
  required?: string[];
  /** 参数依赖关系：参数之间的依赖和替代关系 */
  dependencies?: Array<{
    param: string;
    alternatives?: string[];
  }>;
  /** 参数提取器：从 context/request 中提取参数（函数签名，实际提取逻辑在验证服务中实现） */
  extractors?: Record<string, string>; // 提取器名称，如 'tripId', 'countryCode'
}

export interface SkillMetadata {
  // ... 原有字段
  /** 输入参数 Schema（可选，用于声明式验证） */
  inputSchema?: SkillInputSchema;
}
```

**优势**：
- ✅ 声明式验证：skill 可以在 metadata 中定义验证规则
- ✅ 类型安全：TypeScript 接口提供类型检查
- ✅ 可扩展：支持未来添加更多验证规则类型

### 3. 实现统一的验证服务 SkillInputValidatorService

**文件**: `src/agent/services/skill-input-validator.service.ts`

**核心功能**：
1. **统一验证入口**：`validate()` 方法
2. **多源验证规则**：
   - 优先使用 `SkillMetadata.inputSchema`（声明式，推荐）
   - 降级到 `SKILL_VALIDATION_RULES` 配置（向后兼容）
3. **参数提取**：支持从 context/request 中提取参数
4. **依赖关系检查**：支持参数替代关系（如 `world` 或 `tripId`）
5. **澄清消息生成**：自动生成用户友好的澄清消息

**验证流程**：
```
输入参数
  ↓
使用提取器填充参数
  ↓
检查必需参数
  ↓
检查依赖关系（替代参数）
  ↓
返回验证结果
```

## 🔄 验证规则来源优先级

1. **SkillMetadata.inputSchema**（声明式，推荐）
   - 定义在 skill 的 metadata 中
   - 类型安全，易于维护
   - 与 skill 定义在一起，便于理解

2. **SKILL_VALIDATION_RULES 配置**（向后兼容）
   - 集中管理验证规则
   - 适用于现有 skill
   - 逐步迁移到声明式验证

3. **无验证规则**（跳过验证）
   - 对于没有验证规则的 skill，跳过验证
   - 避免误报
