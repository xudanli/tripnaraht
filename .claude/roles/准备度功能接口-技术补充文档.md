## 📋 一、错误处理细节

### 1.1 错误分类与处理策略

**错误类型**：
- `TIMEOUT`: 超时错误 → 降级到 DeepSeek
- `RATE_LIMIT`: 限流错误 → 等待后重试
- `SCHEMA_VALIDATION`: Schema 验证失败 → 重试 2 次
- `NETWORK_ERROR`: 网络错误 → 重试 1 次后降级
- `API_ERROR`: API 错误 → 降级到 DeepSeek
- `UNKNOWN_ERROR`: 未知错误 → 降级到基础功能

**实现位置**：`src/trips/readiness/services/readiness-ai.service.ts`

**核心原则**：
- **多层降级**：Claude → DeepSeek → 基础功能
- **重试机制**：根据错误类型选择重试策略
- **部分失败**：部分 AI 增强失败不影响其他功能

---

### 1.2 超时处理

**超时配置**：
- Claude 3.5 Sonnet: 5 秒
- DeepSeek: 3.5 秒
- RAG 检索: 2 秒

**实现方式**：使用 `Promise.race()` 实现超时控制

---

### 1.3 部分失败处理

**策略**：使用 `Promise.allSettled()` 并行调用，支持部分成功

**原则**：
- 成功的功能正常显示
- 失败的功能降级到基础结果
- 记录失败信息用于监控

## 📊 二、监控告警配置

### 2.1 Prometheus 告警规则

**性能告警**：
- P95 延迟 > 4s → Warning
- P99 延迟 > 8s → Critical

**成本告警**：
- 单次请求成本 > $0.1 → Warning
- 日总成本 > $200 → Critical

**质量告警**：
- 成功率 < 90% → Warning
- 降级率 > 10% → Warning
- 缓存命中率 < 70% → Warning

**实现位置**：`monitoring/prometheus-alerts.yml`

---

### 2.2 告警通知

**通知方式**：
- Warning: Slack
- Critical: Slack + Email + PagerDuty

**实现位置**：`monitoring/alertmanager.yml`

## 💾 三、缓存策略细节

### 3.1 缓存失效策略

**失效场景**：
1. 行程信息变更 → 失效相关缓存
2. 用户偏好变更 → 失效用户 AI 增强缓存
3. 规则引擎更新 → 失效所有缓存（通过版本号）
4. 手动失效 → 管理员操作

**实现位置**：`src/trips/readiness/services/readiness-cache.service.ts`

---

### 3.2 缓存预热机制

**预热时机**：
- 行程创建时（异步）
- 行程更新时（先失效，再预热）

**预热内容**：
- 基础准备度检查结果
- AI 增强结果（如果启用）

**实现位置**：`src/trips/readiness/services/readiness-cache.service.ts`

---

### 3.3 缓存一致性保证

**版本号机制**：
- 每个缓存项包含版本号
- 规则引擎更新时更新全局版本号
- 获取缓存时检查版本一致性

**实现位置**：`src/trips/readiness/services/readiness-cache.service.ts`

## 🚩 四、Feature Flag 实现

### 4.1 数据库模型

**模型定义**：
```prisma
model UserFeatureFlag {
  id        String   @id @default(uuid())
  userId    String
  feature   String
  enabled   Boolean
  metadata  Json?
  @@unique([userId, feature])
}

model GlobalFeatureFlag {
  id        String   @id @default(uuid())
  feature   String   @unique
  enabled   Boolean
  metadata  Json?
}
```

**实现位置**：`prisma/schema.prisma`

### 4.2 Feature Flag 服务

**优先级**：
1. 环境变量（最高）
