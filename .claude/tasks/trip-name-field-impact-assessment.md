# 行程名称字段新增 - 影响范围评估

## 📋 执行摘要

**功能**：为 Trip 模型新增 `name` 字段（行程名称）  
**影响范围**：数据库、后端 API、前端展示  
**风险等级**：低（向后兼容，可选字段）  
**预计工期**：8 个工作日

---

## 🔍 影响范围详细分析

### 1. 数据库层（Prisma Schema）

**影响文件**：
- `prisma/schema.prisma` - Trip 模型定义

**变更内容**：
```prisma
model Trip {
  // ... 现有字段
  name String? @db.VarChar(200)  // 新增：可选字段，最大长度 200
  // ... 其他字段
}
```

**影响评估**：
- ✅ **低风险**：新增可选字段，不影响现有数据
- ✅ **向后兼容**：已有行程 `name` 为 `null`，查询时自动生成默认名称
- ⚠️ **需要迁移**：需要数据库迁移脚本为已有数据生成默认名称

**依赖关系**：
- 无其他表依赖此字段
- 不影响现有索引和查询性能

---

### 2. DTO 层（数据传输对象）

**影响文件**：
- `src/trips/dto/create-trip.dto.ts` - 创建行程 DTO
- `src/trips/dto/update-trip.dto.ts` - 更新行程 DTO（继承自 CreateTripDto）

**变更内容**：
```typescript
// CreateTripDto 新增字段
@ApiPropertyOptional({
  description: '行程名称（1-200 字符）',
  example: '冰岛环岛游',
  maxLength: 200,
})
@IsOptional()
@IsString()
@Length(1, 200)
name?: string;
```

**影响评估**：
- ✅ **低风险**：可选字段，现有 API 调用不受影响
- ✅ **向后兼容**：不提供 `name` 字段时，使用默认值

**依赖关系**：
- 影响所有使用 `CreateTripDto` 和 `UpdateTripDto` 的接口

---

### 3. Service 层（业务逻辑）

**影响文件**：
- `src/trips/trips.service.ts` - 行程服务
  - `create()` 方法 - 创建行程时处理名称
  - `update()` 方法 - 更新行程时处理名称
  - `findOne()` 方法 - 查询行程时返回名称
  - `findByUserId()` 方法 - 查询用户行程列表时返回名称

**变更内容**：
```typescript

const tripName = dto.name || this.generateDefaultTripName({
  destination: dto.destination,
  startDate: dto.startDate,
});

// 更新行程时
if (dto.name !== undefined) {
  updateData.name = dto.name;
}

// 查询时
// name 字段自动包含在返回结果中
```

**影响评估**：
- ✅ **低风险**：逻辑简单，不影响现有功能
- ⚠️ **需要测试**：需要测试默认名称生成逻辑

**依赖关系**：
- 需要实现 `generateDefaultTripName()` 辅助方法
- 需要实现 `getDestinationName()` 方法（国家代码到名称映射）

### 7. 数据迁移

**影响范围**：
- 所有已有行程数据（`name` 字段为 `null`）

**迁移脚本**：
```sql
-- 为已有行程生成默认名称
UPDATE "Trip"
SET "name" = CONCAT(
  CASE 
    WHEN "destination" = 'IS' THEN '冰岛'
    WHEN "destination" = 'JP' THEN '日本'
    -- ... 其他映射
    ELSE UPPER("destination")
  END,
  ' ',
  TO_CHAR("startDate", 'YYYY-MM-DD')
)
WHERE "name" IS NULL;
```

**影响评估**：
- ⚠️ **需要谨慎执行**：生产环境数据迁移需要备份和回滚方案
- ✅ **低风险**：只读操作，不影响现有数据完整性
- ⚠️ **性能考虑**：如果数据量大，需要分批迁移

**依赖关系**：
- 需要在数据库迁移完成后执行
- 需要验证迁移结果
