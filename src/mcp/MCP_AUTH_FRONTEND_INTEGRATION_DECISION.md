# MCP 服务前端授权集成决策

## 📋 文档说明

**目标受众**: 产品经理、前端开发团队  
**文档目的**: 确定前端应集成哪些 MCP 服务的用户授权功能  
**决策日期**: 2026-02-06

---

## 🎯 执行摘要

### 核心决策

**前端应集成用户授权的 MCP 服务**:
1. ✅ **Google Calendar MCP** - 必须（用户个人日历）
2. ✅ **Browserbase MCP** - 推荐（按需使用）
3. ⚠️ **Airbnb MCP** - 可选（如果支持用户账户）
4. ⚠️ **Amadeus MCP** - 可选（如果支持用户账户）

**前端不需要集成的服务**:
- ❌ **PostgreSQL MCP** - 管理员配置（数据库连接）
- ❌ **Exa MCP** - 管理员配置（API Key）
- ❌ **Booking.com MCP** - 管理员配置（API Key）

---

## 📊 MCP 服务授权需求分析

### 1. Google Calendar MCP ⭐⭐⭐⭐⭐

**授权类型**: **用户级别 OAuth**（必须）

**业务原因**:
- ✅ **访问用户个人数据** - 每个用户有自己的 Google 日历
- ✅ **数据隐私** - 日历数据是个人隐私，必须用户授权
- ✅ **功能依赖** - 所有功能都需要访问用户的日历

**授权场景**:
- 用户首次使用日历同步功能
- 用户想要查看自己的日历事件
- 用户想要创建/更新/删除日历事件

**前端集成优先级**: **P0（最高）**

**用户体验**:
- 用户点击"连接 Google 日历"
- 跳转到 Google OAuth 授权页面
- 授权完成后，自动返回应用
- 显示授权成功状态

---

### 2. Browserbase MCP ⭐⭐⭐⭐

**授权类型**: **服务级别 OAuth**（推荐）

**业务原因**:
- ✅ **按需使用** - 不是所有用户都需要浏览器自动化功能
- ✅ **成本控制** - 按使用量计费，用户授权后可控制使用
- ⚠️ **技术复杂性** - 授权流程相对复杂，需要 connectionId 管理

**授权场景**:
- 用户首次使用数据抓取功能
- 用户想要使用浏览器自动化功能
- 授权过期需要重新授权

**前端集成优先级**: **P1（高）**

**用户体验**:
- 用户点击"启用浏览器自动化"
- 显示授权说明（为什么需要授权）
- 跳转到授权页面
- 授权完成后，保存 connectionId
- 显示授权状态和使用统计

**注意事项**:
- ⚠️ 授权流程需要用户手动完成（无法自动化）
- ⚠️ connectionId 需要保存到用户配置中
- ⚠️ 授权状态需要定期检查

---

### 3. Airbnb MCP ⭐⭐⭐

**授权类型**: **服务级别 OAuth**（可选）

**业务原因**:
- ⚠️ **功能依赖** - 如果 Airbnb 服务需要用户账户，则需要授权
- ⚠️ **数据访问** - 如果访问用户自己的预订数据，需要授权
- ✅ **搜索功能** - 如果只是搜索房源，可能不需要用户授权

**授权场景**:
- 用户想要访问自己的 Airbnb 预订
- 用户想要管理自己的房源（如果适用）

**前端集成优先级**: **P2（中）**

**用户体验**:
- 仅在需要用户数据时提示授权
- 搜索功能无需授权即可使用

**决策建议**: 
- **先不集成** - 如果搜索功能不需要授权
- **后续评估** - 根据实际业务需求决定

---

### 4. Amadeus MCP ⭐⭐

**授权类型**: **服务级别 OAuth**（可选）

**业务原因**:
- ⚠️ **功能依赖** - 航班搜索通常不需要用户账户
- ⚠️ **数据访问** - 如果只是搜索，不需要用户授权
- ✅ **API Key 配置** - 可能只需要管理员配置 API Key

**授权场景**:
- 如果 Amadeus 服务需要用户账户（不太可能）
- 如果访问用户自己的预订数据

**前端集成优先级**: **P3（低）**

**决策建议**: 
- **暂不集成** - 航班搜索通常不需要用户授权
- **监控需求** - 如果后续需要用户数据，再考虑集成

---

### 5. PostgreSQL MCP ❌

**授权类型**: **管理员配置**（不需要用户授权）

**业务原因**:
- ✅ **数据库连接** - 数据库连接由管理员配置
- ✅ **权限控制** - 通过数据库用户权限控制，不需要前端授权
- ✅ **安全性** - 数据库凭证不应暴露给前端

**前端集成优先级**: **不需要**

---

### 6. Exa MCP ❌

**授权类型**: **管理员配置**（不需要用户授权）

**业务原因**:
- ✅ **API Key** - 使用服务级别的 API Key
- ✅ **统一使用** - 所有用户共享同一个 API Key
- ✅ **成本管理** - 由管理员统一管理成本

**前端集成优先级**: **不需要**

---

### 7. Booking.com MCP ❌

**授权类型**: **管理员配置**（不需要用户授权）

**业务原因**:
- ✅ **API Key** - 使用服务级别的 API Key
- ✅ **统一使用** - 所有用户共享同一个 API Key

**前端集成优先级**: **不需要**

## 💡 前端授权集成方案

### 方案 1: 统一授权管理组件（推荐）⭐

**设计思路**:
- 创建一个统一的授权管理组件
- 支持多个 MCP 服务的授权
- 统一的授权流程和状态管理

**组件结构**:
```typescript
// MCP 授权管理组件
<McpAuthManager>
  <AuthCard service="google-calendar" />
  <AuthCard service="browserbase" />
  <AuthCard service="airbnb" />
</McpAuthManager>
```

**功能**:
- ✅ 显示每个服务的授权状态
- ✅ 一键授权/重新授权
- ✅ 授权状态实时更新
- ✅ 授权说明和帮助

**优点**:
- 统一的用户体验
- 易于维护和扩展
- 清晰的授权状态展示

---

### 方案 2: 按需授权（轻量级）⭐

**设计思路**:
- 在需要使用功能时提示授权
- 不需要单独的授权管理页面

**实现方式**:
- 功能入口处检查授权状态
- 未授权时显示授权提示
- 点击后跳转授权流程

**优点**:
- 用户体验更流畅
- 减少不必要的授权步骤
- 降低用户认知负担

**缺点**:
- 授权状态分散，不易管理

---

### 方案 3: 混合方案（推荐）⭐⭐

**设计思路**:
- 设置页面：统一管理所有授权
- 功能入口：按需提示授权

**实现方式**:
1. **设置页面** - 显示所有服务的授权状态和管理
2. **功能入口** - 使用功能时检查授权，未授权时提示

**优点**:
- 兼顾统一管理和按需授权
- 用户体验最佳
- 灵活性高

## 📋 前端集成清单

### 必须集成的服务（P0）

#### 1. Google Calendar MCP

**接口**:
- `GET /api/google-calendar/auth/status` - 检查授权状态
- `GET /api/google-calendar/auth/url` - 获取授权 URL
- `POST /api/google-calendar/auth/verify` - 验证授权

**集成位置**:
- ✅ 设置页面 - 账户设置 > 第三方服务
- ✅ 功能入口 - 日历同步功能入口

**用户体验流程**:
```
用户点击"连接 Google 日历" 
→ 调用 /auth/url 获取授权 URL
→ 跳转到 Google OAuth 页面
→ 用户完成授权
→ 自动返回应用
→ 调用 /auth/verify 验证授权
→ 显示授权成功
```

---

### 推荐集成的服务（P1）

#### 2. Browserbase MCP

**接口**:
- `GET /api/browserbase-mcp/auth/url` - 获取授权 URL
- `POST /api/browserbase-mcp/auth/verify` - 验证授权状态

**集成位置**:
- ✅ 设置页面 - 高级功能 > 浏览器自动化
- ✅ 功能入口 - 数据抓取功能入口

**用户体验流程**:
```
用户点击"启用浏览器自动化"
→ 显示授权说明（为什么需要授权）
→ 调用 /auth/url 获取授权 URL
→ 跳转到授权页面
→ 用户完成授权
→ 保存 connectionId 到用户配置

```

**特殊处理**:
- ⚠️ connectionId 需要保存到用户配置

- ⚠️ 授权过期时需要重新授权

## 🔍 风险评估

### 技术风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| OAuth 流程复杂 | 中 | 中 | 使用成熟的 OAuth 库，提供清晰的指引 |
| 授权状态不同步 | 中 | 低 | 定期检查授权状态，实现状态缓存 |
| connectionId 丢失 | 高 | 低 | 保存到用户配置，提供恢复机制 |

### 业务风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| 用户拒绝授权 | 高 | 中 | 提供清晰的授权说明，展示授权价值 |
| 授权流程中断 | 中 | 低 | 实现授权流程恢复机制 |
| 授权过期未提醒 | 中 | 中 | 实现授权过期检测和提醒 |

## ✅ 最终决策

### 前端应集成的授权服务

1. ✅ **Google Calendar MCP** - **必须集成**（P0）
   - 理由: 访问用户个人数据，功能必需
   - 优先级: 最高

2. ✅ **Browserbase MCP** - **推荐集成**（P1）
   - 理由: 按需使用，成本控制
   - 优先级: 高

3. ⚠️ **Airbnb MCP** - **暂不集成**（P2）
   - 理由: 搜索功能可能不需要授权，等待需求明确
   - 优先级: 中

4. ❌ **Amadeus MCP** - **不集成**（P3）
   - 理由: 航班搜索不需要用户授权
   - 优先级: 低

### 实施建议

1. **先做 Google Calendar** - 核心功能，用户需求明确
2. **再做 Browserbase** - 高级功能，按需使用
3. **后续评估 Airbnb** - 根据实际业务需求决定
