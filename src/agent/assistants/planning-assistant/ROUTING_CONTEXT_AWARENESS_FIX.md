# 路由上下文感知修复

## 问题分析

### 问题1: 路由识别失败
用户输入"推荐冰岛酒店"被错误路由到 `recommendations`（目的地推荐），而不是 `hotel`（酒店搜索）。

**根本原因**:
1. LLM 路由优先执行，可能将"推荐冰岛酒店"误判为目的地推荐
2. 关键词路由的置信度（0.85）低于 LLM 路由阈值（0.7），导致被 LLM 结果覆盖
3. 关键词路由没有提取目的地参数

### 问题2: 服务不可用
日志显示 `HotelDirectService not available`，服务没有正确注入。

### 问题3: 缺乏上下文感知
在规划工作台中，用户已经选定了目的地（如"冰岛"），但助手没有利用这个上下文信息，导致：
- "推荐酒店"时不知道是哪个目的地的酒店
- 无法提供更精准的建议

## 修复方案

### 1. 调整路由优先级 ✅

**修改文件**: `smart-router.service.ts`

- **先进行快速关键词检查**：如果匹配到具体服务（hotel、airbnb、restaurant 等）且置信度 >= 0.8，直接返回，不调用 LLM
- **提高具体服务的置信度**：
  - 酒店：0.85 → 0.9
  - Airbnb：0.9 → 0.95
  - 餐厅：0.85 → 0.9
  - 天气：0.9 → 0.95
  - 航班：0.85 → 0.9
  - 铁路：0.85 → 0.9
- **增强关键词匹配**：添加"推荐+具体服务"的组合检查（如"推荐+酒店"）

### 2. 改进目的地提取 ✅

**修改文件**: `smart-router.service.ts`

- 在关键词路由中提取目的地参数
- 优先使用会话状态中的 `selectedDestination`
- 如果会话中没有，则从消息中提取（移除"推荐"、"酒店"等关键词）

### 3. 上下文感知增强 ✅

**修改文件**: 
- `planning-assistant-v2.service.ts`
- `smart-router.service.ts`

**改进点**:
1. **会话状态传递**：在路由时传递完整的会话状态，包括 `selectedDestination`
2. **目的地优先级**：
   - 优先使用会话中的 `selectedDestination`
   - 其次使用路由结果中的 `destination`
   - 最后从消息中提取
3. **LLM Prompt 增强**：在 LLM 路由的 prompt 中包含已选定的目的地信息

### 4. 错误处理改进 ✅

**修改文件**: `planning-assistant-v2.service.ts`

- 当服务不可用时，返回明确的错误消息，而不是静默回退到对话
- 添加服务注入状态日志，便于调试
- 改进错误消息，提示用户联系技术支持

## 修复后的行为

### 场景1: 用户在规划工作台中已选定"冰岛"
- 用户输入："推荐酒店"
- **修复前**: 路由到 `recommendations`，推荐其他目的地
- **修复后**: 
  1. 关键词路由识别为 `hotel`（置信度 0.9）
  2. 使用会话中的目的地"冰岛"
  3. 路由到酒店搜索服务，返回冰岛的酒店列表

### 场景2: 用户直接输入"推荐冰岛酒店"
- **修复前**: LLM 路由误判为 `recommendations`
- **修复后**:
  1. 关键词路由先执行，识别为 `hotel`（置信度 0.9）
  2. 提取目的地"冰岛"
  3. 直接返回，不调用 LLM
  4. 路由到酒店搜索服务

### 场景3: 服务不可用
- **修复前**: 静默回退到对话，用户不知道为什么没有结果
- **修复后**: 返回明确的错误消息："酒店搜索服务暂不可用，请联系技术支持。"

## 代码变更

### 1. `smart-router.service.ts`
- `route()` 方法：添加 `selectedDestination` 支持
- `routeByKeywords()` 方法：优先使用会话中的目的地
- `routeWithLLM()` 方法：在 prompt 中包含已选定的目的地

### 2. `planning-assistant-v2.service.ts`
- `chat()` 方法：传递完整的会话状态（包括 `selectedDestination`）
- `hotel` case：优先使用会话中的目的地，改进错误处理
