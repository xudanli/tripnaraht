# 规划工作台的三人格定位

## 概述

规划工作台（Planning Workspace）是 TripNARA 的核心规划系统，通过 LangGraph Orchestrator 编排多个 Agent 来协同工作。三人格系统（Abu、Dr.Dre、Neptune）被封装在 `TripNaraCoreToolService` 中，作为 `CORE_DECISION` 工具被 LangGraph 调用。

与行程详情页不同，规划工作台中的三人格定位更加"底层"和"工具化"：
- **行程详情页**：展示三人格的决策结果，面向用户
- **规划工作台**：调用三人格进行决策计算，面向系统内部

---

## 一、架构定位

### 1.1 在 LangGraph 架构中的位置

```
用户查询
  ↓
LangGraph Orchestrator（调度员）
  ↓
  ├─→ Planner Agent（意图识别、参数提取）
  ├─→ Compliance Agent（合规检查，可选）
  ├─→ Local Insight Agent（本地洞察，可选）
  └─→ CORE_DECISION（核心决策工具）
        ↓
        TripNaraCoreToolService
          ↓
          StrategyOrchestratorService
            ↓
            ├─→ Abu Strategy（安全否决者）
            ├─→ Dr.Dre Strategy（节奏修复者）
            └─→ Neptune Strategy（空间修复者）
  ↓
Narrator Agent（生成用户友好的解释）
  ↓
最终响应
```

### 1.2 核心组件

#### TripNaraCoreToolService

**文件位置**：`src/trips/decision/tools/tripnara-core-tool.service.ts`

**职责**：
- 将三人格系统封装成可以被 LangGraph 调用的工具
- 将用户查询参数映射到 `WorldModelContext`
- 执行策略编排（调用 StrategyOrchestratorService）
- 将决策结果转换为工具输出格式

**设计原则**：
- 保持 Hard Core 的确定性逻辑不变
- 提供标准化的工具调用接口（兼容 MCP / OpenAPI）
- 让 LangGraph 作为"调度员"而非"驾驶员"

#### StrategyOrchestratorService

**文件位置**：`src/trips/decision/services/strategy-orchestrator.service.ts`

**职责**：
- 按顺序执行三人格的决策流程：Abu → Dr.Dre → Neptune
- 协调三人格的协同工作
- 记录决策日志

## 二、三人格在规划工作台中的定位

### 2.1 Abu（安全否决者）

**在规划工作台中的定位**：
- **工具角色**：作为 `CORE_DECISION` 工具的第一个执行节点
- **调用时机**：在 Planner Agent 提取参数后，立即执行安全检查
- **输入来源**：`WorldModelContext.physical` 和 `complianceEvidence`
- **输出结果**：`ALLOW` 或 `REJECT`

**执行流程**：
```typescript
// 1. LangGraph 调用 CORE_DECISION 工具
coreToolInput = {
  countryCode: 'IS',
  month: 7,
  routeDirectionId: 'rd-001',
  humanCapability: { ... },
  initialPlan: routePlanDraft
};

// 2. TripNaraCoreToolService 构建 WorldModelContext
world = {
  physical: physicalRealityModel,
  human: humanCapabilityModel,
  philosophy: routePhilosophy
};

// 3. StrategyOrchestratorService 调用 Abu
abuResult = await abuStrategy.evaluate(world, plan);

// 4. 如果 Abu 拒绝，流程立即终止
if (!abuResult.allowed) {
  return {
    allowed: false,
    action: 'REJECT',
    logs: abuResult.logs
  };
}
```

**特点**：
- 不依赖用户偏好或体验需求
- 只基于物理现实和合规性
- 如果拒绝，整个规划流程终止

### 2.2 Dr.Dre（节奏修复者）

**在规划工作台中的定位**：
- **工具角色**：作为 `CORE_DECISION` 工具的第二个执行节点
- **调用时机**：在 Abu 通过后，执行节奏调整
- **输入来源**：`WorldModelContext.human` 和 `HumanCapabilityModel`
- **输出结果**：`ALLOW` 或 `ADJUST`（调整后的计划）

**执行流程**：
```typescript
// 1. Abu 通过后，继续执行 Dr.Dre
dreResult = await drDreStrategy.evaluate(world, currentPlan);

// 2. 如果 Dr.Dre 调整了计划，使用调整后的计划
if (dreResult.updatedPlan) {
  currentPlan = dreResult.updatedPlan;
}

// 3. 继续执行 Neptune
```

**特点**：
- 基于人体能力模型驱动
- 可以调整计划结构（拆分天数、插入休息日）
- 不能替换空间要素（只能 ADJUST，不能 REPLACE）

### 2.3 Neptune（空间修复者）

**在规划工作台中的定位**：
- **工具角色**：作为 `CORE_DECISION` 工具的第三个执行节点
- **调用时机**：在 Dr.Dre 调整后，执行空间修复
- **输入来源**：`WorldModelContext.philosophy` 和空间问题检测结果
- **输出结果**：`ALLOW` 或 `REPLACE`（替换后的计划）

**执行流程**：
```typescript
// 1. Dr.Dre 调整后，继续执行 Neptune
nepResult = await neptuneStrategy.evaluate(world, currentPlan);

// 2. 如果 Neptune 替换了计划，使用替换后的计划
if (nepResult.updatedPlan) {
  currentPlan = nepResult.updatedPlan;
}

// 3. 返回最终结果
return {
  allowed: true,
  action: 'ALLOW' | 'ADJUST' | 'REPLACE',
  plan: currentPlan,
  logs: [abuLogs, dreLogs, nepLogs]
};
```

**特点**：
- 保持 RouteDirection 哲学不变
- 可以替换空间要素（入口、POI、路段）
- 不能忽略硬约束或改变路线哲学

## 三、工具调用接口

### 3.1 输入接口（TripNaraCoreToolInput）

```typescript
interface TripNaraCoreToolInput {
  /** 国家代码 */
  countryCode: string;
  
  /** 月份（1-12） */
  month: number;
  
  /** 路线方向 ID */
  routeDirectionId: string;
  
  /** 用户能力参数（从 HumanCapabilityModel 投影） */
  humanCapability: {
    maxDailyAscentM?: number;
    rollingAscent3DaysM?: number;
    maxSlopePct?: number;
    preferredPace?: 'SLOW' | 'MEDIUM' | 'FAST';
    riskTolerance?: 'LOW' | 'MEDIUM' | 'HIGH';
    highAltitudeExperience?: 'NONE' | 'BASIC' | 'ADVANCED';
    specialConstraints?: string[];
  };
  
  /** 初始路线计划（可选，如果已有草案） */
  initialPlan?: RoutePlanDraft;
  
  /** 元数据（用于 LangGraph 传递上下文） */
  metadata?: Record<string, any>;
}
```

### 3.2 输出接口（TripNaraCoreToolOutput）

```typescript
interface TripNaraCoreToolOutput {
  /** 是否允许 */
  allowed: boolean;
  
  /** 最终计划（如果被拒绝则为 null） */
  plan: RoutePlanDraft | null;
  
  /** 决策动作 */
  action: 'ALLOW' | 'REJECT' | 'ADJUST' | 'REPLACE';
  
  /** 决策日志（用于解释和调试） */
  logs: Array<{
    persona: 'ABU' | 'DR_DRE' | 'NEPTUNE';
    action: string;
    explanation: string;
    decisionSource: 'PHYSICAL' | 'HUMAN' | 'PHILOSOPHY' | 'HEURISTIC';
  }>;
  
  /** 可读的解释（用于 Narrator Agent） */
  explanation: string;
  
  /** 元数据（用于 LangGraph 传递上下文） */
  metadata?: Record<string, any>;
}
```

## 四、执行流程

### 4.1 完整执行流程

```typescript
// 1. 用户查询
userQuery: "我想7月去冰岛，走高地路线，节奏不要太紧张"

// 2. Planner Agent 分析查询
plannerResult = await plannerAgent.analyzeQuery(userQuery);
// 输出：
// {
//   intent: "规划行程",
//   extractedParams: {
//     countryCode: "IS",
//     month: 7,
//     routeDirectionId: "rd-iceland-highlands",
//     humanCapability: { preferredPace: "SLOW", ... }
//   },
//   nextStep: "CORE_DECISION"
// }

// 3. LangGraph 调用 CORE_DECISION 工具
coreToolInput = buildCoreToolInput(plannerResult.extractedParams);
coreToolOutput = await coreTool.execute(coreToolInput);

// 4. TripNaraCoreToolService 内部执行流程
async execute(input: TripNaraCoreToolInput) {
  // 4.1 构建 WorldModelContext
  const world = await this.buildWorldModelContext(input);
  
  // 4.2 构建或使用初始计划
  const plan = input.initialPlan || await this.buildInitialPlan(input);
  
  // 4.3 执行策略编排（三人格执行）
  const result = await this.orchestrator.run(world, plan);
  // 内部执行：
  // - Abu.evaluate(world, plan) → ALLOW/REJECT
  // - Dr.Dre.evaluate(world, plan) → ADJUST (if needed)
  // - Neptune.evaluate(world, plan) → REPLACE (if needed)
  
  // 4.4 转换为工具输出格式
  return this.convertToToolOutput(result, input);
}

// 5. Narrator Agent 生成用户友好的解释
explanation = await narratorAgent.generateExplanation(
  coreToolOutput,
  complianceResult
);

// 6. 返回最终响应
finalResponse = explanation;
```

### 4.2 策略编排流程（StrategyOrchestratorService.run）

```typescript
async run(world: WorldModelContext, plan: RoutePlanDraft) {
  const allLogs: DecisionLogEntry[] = [];
  let currentPlan = plan;
  
  // 1. Abu 评估（安全否决者）
  const abuResult = await this.abu.evaluate(world, currentPlan);
  allLogs.push(...abuResult.logs);
  
  if (!abuResult.allowed) {
    return {
      plan: null,
      logs: allLogs,
      allowed: false,
      finalAction: 'REJECT'
    };
  }
  
  // 2. Dr.Dre 评估（节奏修复者）
  const dreResult = await this.dre.evaluate(world, currentPlan);
  allLogs.push(...dreResult.logs);
  
  if (dreResult.updatedPlan) {
    currentPlan = dreResult.updatedPlan;
  }
  
  // 3. Neptune 评估（空间修复者）
  const nepResult = await this.nep.evaluate(world, currentPlan);
  allLogs.push(...nepResult.logs);
  
  if (nepResult.updatedPlan) {
    currentPlan = nepResult.updatedPlan;
  }
  
  // 4. 返回最终结果
  return {
    plan: currentPlan,
    logs: allLogs,
    allowed: true,
    finalAction: determineFinalAction(allLogs)
  };
}
```

## 五、与行程详情页的对比

### 5.1 定位差异

| 维度 | 规划工作台 | 行程详情页 |
|------|-----------|-----------|
| **定位** | 工具/服务层 | 展示层 |
| **调用者** | LangGraph Orchestrator | 前端用户界面 |
| **输入** | `TripNaraCoreToolInput` | 行程ID和查询参数 |
| **输出** | `TripNaraCoreToolOutput` | 决策日志、人格提醒、证据链 |
| **用途** | 执行决策计算 | 展示决策结果 |
| **可见性** | 系统内部 | 用户可见 |

### 5.2 数据流对比

**规划工作台数据流**：
```
用户查询
  ↓
Planner Agent（提取参数）
  ↓
CORE_DECISION 工具（三人格执行）
  ↓
Narrator Agent（生成解释）
  ↓
最终响应（文本）
```

**行程详情页数据流**：
```
用户查看行程
  ↓
前端调用 API
  ↓
后端查询决策日志
  ↓
返回决策日志、人格提醒、证据链
  ↓
前端展示（时间线、卡片、可视化）
```

### 5.3 三人格在不同场景中的表现

| 人格 | 规划工作台 | 行程详情页 |
|------|-----------|-----------|
| **Abu** | 执行安全检查，返回 ALLOW/REJECT | 展示安全检查和拒绝原因 |
| **Dr.Dre** | 执行节奏调整，返回 ADJUST 结果 | 展示节奏调整建议和疲劳分析 |
| **Neptune** | 执行空间修复，返回 REPLACE 结果 | 展示空间替换记录和路线变化 |

## 七、设计原则

### 7.1 工具化设计

- 三人格系统被封装成工具，可以被 LangGraph 或其他系统调用
- 提供标准化的接口，不依赖特定的调用方式
- 保持确定性逻辑，避免非确定性行为

### 7.2 职责分离

- **LangGraph**：负责编排和调度，不负责决策逻辑
- **TripNaraCoreToolService**：负责参数映射和结果转换
- **StrategyOrchestratorService**：负责三人格的执行顺序
- **三人格策略**：负责各自的决策逻辑

### 7.3 可扩展性

- 通过接口定义，可以替换不同的实现
- 支持不同的调用方式（LangGraph、直接调用、MCP 等）
- 可以添加新的策略或工具

## 九、注意事项

1. **工具化定位**：
   - 规划工作台中的三人格是"工具"而非"界面"
   - 不直接面向用户，而是被其他系统调用

2. **确定性逻辑**：
   - 三人格的决策逻辑必须是确定性的
   - 相同的输入应该产生相同的输出
   - 避免依赖外部状态或随机性

3. **错误处理**：
   - 工具调用失败时，应该返回明确的错误信息
   - 不应该抛出未捕获的异常

4. **性能考虑**：
   - 工具调用应该是高效的
   - 避免阻塞 LangGraph 的执行流程
   - 考虑使用缓存优化重复计算

5. **可测试性**：
   - 工具接口应该易于测试
   - 可以模拟输入和验证输出
   - 支持单元测试和集成测试

## 十、总结

规划工作台中的三人格定位：

1. **工具化**：被封装成 `TripNaraCoreToolService`，作为工具被调用
2. **系统内部**：不直接面向用户，而是被 LangGraph Orchestrator 调用
3. **确定性**：决策逻辑是确定性的，不依赖外部状态
4. **标准化**：提供标准化的输入/输出接口
5. **可扩展**：支持不同的调用方式和扩展点

与行程详情页不同，规划工作台中的三人格更加"底层"和"工具化"，专注于执行决策计算，而不负责用户展示。
