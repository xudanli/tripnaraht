# 行程详情页的证据、风险、决策数据计算逻辑

## 概述

行程详情页的数据计算主要分为三个维度：
1. **证据（Evidence）**：解释"为什么这样安排"的证据链
2. **风险（Risk）**：基于DEM数据计算的风险评分
3. **决策（Decision）**：决策引擎的决策过程和结果

所有计算都在计划生成阶段完成，并存储在决策日志（DecisionRunLog）中。

## 一、证据（Evidence）计算逻辑

### 1.1 证据链服务（DEMEvidenceChainService）

**文件位置**：`src/trips/decision/services/dem-evidence-chain.service.ts`

**主要方法**：
- `generateEvidenceChain()`: 生成完整的证据链

**计算流程**：

#### 步骤1：生成计划级证据
```typescript
generatePlanEvidence(plan, routeSegmentation, planRiskScore, selectedRouteDirection)
```

**计算内容**：
- **路线选择原因**：从 `selectedRouteDirection` 提取匹配度最高的原因
- **拆段证据**：
  - 总距离（米）
  - 总爬升（米）
  - 过陡段数量
  - 能量断点数量
  - 强制休息点数量
- **风险证据**：
  - 连续高海拔天数
  - 连续上升高度（米）
  - 坡度集中区间数量
  - 总风险评分

#### 步骤2：生成每日证据
```typescript
generateDayEvidence(day, routeSegmentation, dailyEnergyBudget, dayRiskScore)
```

**计算内容**：
- **地形证据（terrainEvidence）**：
  - `maxElevation`: 最高海拔（从 `day.terrainFacts.maxElevation`）
  - `totalAscent`: 累计爬升（从 `day.terrainFacts.totalAscent`）
  - `steepSections`: 过陡段数量（从 `routeSegmentation.steepSections`）
  - `mandatoryRestPoints`: 强制休息点数量
  - `energyBreakpoints`: 能量断点数量

- **体力证据（energyEvidence）**：
  - `totalEnergyCost`: 总体力消耗（从 `dailyEnergyBudget.totalEnergyCost`）
  - `maxEnergyBudget`: 最大体力预算（从 `dailyEnergyBudget.maxEnergyCost`）
  - `energyRatio`: 体力消耗比例（`totalEnergyCost / maxEnergyBudget`）
  - `exceeded`: 是否超过预算

- **风险证据（riskEvidence）**：
  - `riskScore`: 风险评分（从 `dayRiskScore.riskScore`）
  - `riskFlags`: 风险标志列表（类型、严重程度、消息）

- **时间槽证据（slotEvidences）**：
  - 为每个时间槽生成证据项
  - 证据类型：`TERRAIN` | `ENERGY` | `RISK` | `SEGMENTATION` | `CONSTRAINT` | `PACE`
  - 包含：证据标题、描述、数据、严重程度、是否影响决策、决策影响类型

#### 步骤3：生成时间槽证据
```typescript
generateSlotEvidence(slot, day, routeSegmentation, dailyEnergyBudget)
```

**计算内容**：
- **活动选择原因（whySelected）**：
  - 从 `slot.reasons` 提取
  - 根据优先级标签（`core`、`anchor`）添加原因

- **时间安排原因（whyThisTime）**：
  - 基于开放时间和移动时间

- **位置原因（whyThisLocation）**：
  - 坐标信息

- **证据项（evidence）**：
  - 高海拔活动证据（海拔 > 3000m）
  - 高爬升活动证据（累计爬升 > 500m）
  - 高体力消耗证据（体力消耗比例 > 80%）
  - 风险标志证据

### 1.2 决策证据服务（DemDecisionEvidenceService）

**文件位置**：`src/trips/decision/services/dem-decision-evidence.service.ts`

**主要方法**：
- `generateEvidencePipeline()`: 生成DEM决策证据管道结果

**计算流程**：

#### 步骤1：生成路段证据
```typescript
generateDecisionEvidence(plan, routeDirection, routeSegmentation)
```

**为每一天生成证据**：
- **海拔剖面（elevationProfile）**：
  - 优先从 `routeSegmentation.elevationProfile` 提取
  - 否则从 `day.terrainFacts` 推断（生成10个点的简化剖面）

- **累计爬升（cumulativeAscent）**：
  - 从 `day.terrainFacts.totalAscent` 获取

- **最大坡度（maxSlopePct）**：
  - 从海拔剖面计算：`(海拔差 / 距离) * 100`
  - 假设每点间隔1km

- **3天滚动窗口累计爬升（rollingAscent3Days）**：
  - 计算当前天及前2天的累计爬升总和

- **疲劳指数（fatigueIndex）**：
  ```
  基础疲劳 = min(累计爬升 / 100, 50)
  坡度疲劳 = 坡度 <= 20% ? 坡度 * 0.5 : 10 + (坡度 - 20) * 1.0
  海拔疲劳 = 海拔 > 3000m ? min((海拔 - 3000) / 100, 30) : 0
  疲劳指数 = min(基础疲劳 + 坡度疲劳 + 海拔疲劳, 100)
  ```

- **违规类型（violation）**：
  - `HARD`: 违反硬约束（最大海拔、最大坡度、快速爬升禁止）
  - `SOFT`: 违反软约束（建议的海拔/爬升限制）
  - `NONE`: 无违规

#### 步骤2：检测连续疲劳
```typescript
detectRollingFatigue(plan, routeDirection)
```

**检测逻辑**：
- 窗口大小：3天
- 默认阈值：2000米（3天累计爬升）
- 遍历所有3天窗口，计算窗口内累计爬升
- 如果超过阈值：
  - `detected = true`
  - 记录开始/结束日期
  - 建议操作：
    - 超过阈值1.5倍 → `INSERT_REST_DAY`（插入休息日）
    - 否则 → `SPLIT_DAYS`（拆分行程）

#### 步骤3：计算走廊质量评分
```typescript
scoreCorridorQuality(routeSegmentation, routeDirection)
```

**计算公式**：
```
总评分 = 
  viewExposureScore * 0.4 + 
  elevationVariance * 0.3 + 
  (100 - slopePenalty) * 0.3
```

**子项计算**：
- **视野暴露度（viewExposureScore，0-100）**：
  - 变化频率 = 海拔变化次数 / 总点数
  - 变化幅度 = 海拔标准差（归一化到500米）
  - `viewExposureScore = (变化频率 * 0.5 + 变化幅度 * 0.5) * 100`

- **海拔变化度（elevationVariance，0-100）**：
  - `elevationVariance = min(海拔范围 / 2000, 1) * 100`

- **坡度惩罚（slopePenalty，0-100，越大越差）**：
  - `slopePenalty = (平均坡度惩罚 * 0.6 + 最大坡度惩罚 * 0.4)`
  - 坡度惩罚 = `min(坡度 / 30, 1) * 100`

#### 步骤4：生成可解释失败说明
```typescript
generateExplainableFailure(evidences, rollingFatigue, corridorQuality)
```

**生成逻辑**：
1. 优先检查硬约束违反
2. 其次检查连续疲劳
3. 最后检查走廊质量（评分 < 40）

## 二、风险（Risk）计算逻辑

### 2.1 风险评分服务（DEMRiskScoringService）

**文件位置**：`src/trips/decision/services/dem-risk-scoring.service.ts`

**主要方法**：
- `calculatePlanRiskScore()`: 计算计划风险评分
- `calculateActivityRiskScore()`: 计算单个活动风险评分

### 2.2 计划风险评分计算

**计算流程**：

#### 步骤1：计算每日风险评分

```typescript
for (每个计划天) {
  // 获取基础数据
  maxElevation = day.terrainFacts.maxElevation
  totalAscent = day.terrainFacts.totalAscent
  
  // 计算连续高海拔天数
  if (maxElevation >= 3000m) {
    consecutiveHighAltitudeDays++
  }
  
  // 计算连续上升
  if (maxElevation > 上一个起始海拔) {
    consecutiveAscent = maxElevation - 起始海拔
  }
  
  // 计算每日风险评分
  dayRiskScore = 0
  
  // 高海拔风险（0-50分）
  if (maxElevation >= 3000m) {
    超出量 = maxElevation - 3000
    dayRiskScore += min(50, (超出量 / 1000) * 50)
    
    // 风险标志
    if (maxElevation >= 4000m) {
      风险标志: HIGH_ALTITUDE, HIGH
    } else if (maxElevation >= 3500m) {
      风险标志: HIGH_ALTITUDE, MEDIUM
    }
  }
  
  // 连续上升风险（0-30分）
  if (totalAscent >= 1200m) {
    dayRiskScore += min(30, (totalAscent / 1200) * 30)
    风险标志: RAPID_ASCENT
  }
}
```

#### 步骤2：计算计划总风险评分

```typescript
// 基础评分
avgDailyRisk = 每日风险评分的平均值

// 惩罚项
consecutiveHighAltitudePenalty = 
  连续高海拔天数 >= 3天 ? min(30, (天数 - 3 + 1) * 10) : 0

consecutiveAscentPenalty = 
  连续上升 >= 1200m ? min(20, (上升 / 1200) * 20) : 0

steepSectionsPenalty = 
  坡度集中区间数量 > 0 ? min(20, 数量 * 5) : 0

// 总风险评分
totalRiskScore = min(100,
  avgDailyRisk * 0.4 +
  consecutiveHighAltitudePenalty +
  consecutiveAscentPenalty +
  steepSectionsPenalty
)
```

#### 步骤3：生成计划级风险标志

- **CONSECUTIVE_HIGH_ALTITUDE**：
  - 条件：连续高海拔天数 >= 3天
  - 严重程度：>= 5天为HIGH，否则MEDIUM

- **CONSECUTIVE_ASCENT**：
  - 条件：连续上升 >= 1200m
  - 严重程度：>= 2000m为HIGH，否则MEDIUM

- **STEEP_CONCENTRATED_SECTIONS**：
  - 条件：坡度集中区间数量 > 0
  - 严重程度：>= 3个为HIGH，否则MEDIUM

### 2.3 活动风险评分计算

**计算公式**：
```typescript
// 高海拔风险（0-100）
altitudeRisk = 
  海拔 >= 3000m ? min(100, ((海拔 - 3000) / 1000) * 100) : 0

// 坡度风险（0-100）
slopeRisk = 
  坡度 >= 15% ? min(100, (|坡度| / 15) * 50) : 0

// 连续上升风险（0-100）
consecutiveAscentRisk = 
  连续上升 >= 1200m ? min(100, (上升 / 1200) * 50) : 0

// 总风险评分（加权平均）
totalRiskScore = min(100,
  altitudeRisk * 0.4 +
  slopeRisk * 0.3 +
  consecutiveAscentRisk * 0.3
)
```

## 三、决策（Decision）数据计算逻辑

### 3.1 决策引擎流程（TripDecisionEngineService）

**文件位置**：`src/trips/decision/trip-decision-engine.service.ts`

**主要方法**：
- `generatePlan()`: 生成初始计划

**计算流程**：

#### 步骤1：生成计划（规划阶段）
- 使用策略服务（Dr.Dre/Neptune/Abu）生成初始计划
- 执行Dry-run模拟

#### 步骤2：计算风险评分（P1.1.3）
```typescript
planRiskScore = await demRiskScoringService.calculatePlanRiskScore(
  plan,
  routeSegmentation
)
```

#### 步骤3：生成证据链（P1.1.4）
```typescript
evidenceChain = demEvidenceChainService.generateEvidenceChain(
  plan,
  routeSegmentation,
  planRiskScore,
  dailyEnergyBudgets,
  selectedRouteDirection
)
```

#### 步骤4：生成DEM决策证据（PART 2）
```typescript
demEvidenceResult = await demDecisionEvidenceService.generateEvidencePipeline(
  plan,
  routeDirectionData,
  routeSegmentation
)
```

**关键逻辑**：
- **强制检查**：没有DEM证据的计划不允许finalize
- **硬约束违反检测**：如果存在HARD violation，记录错误
- **连续疲劳处理**：
  - 如果检测到连续疲劳且建议操作是 `INSERT_REST_DAY`
  - Dr.Dre自动在疲劳开始后插入休息日

#### 步骤5：构建决策日志（DecisionRunLog）

**数据结构**：
```typescript
{
  // 计划基本信息
  plan: TripPlan,
  
  // 风险评分
  riskScore: PlanRiskScore,
  
  // 证据链
  evidenceChain: RouteEvidenceChain,
  
  // DEM决策证据
  demEvidence: DemEvidencePipelineResult,
  
  // Dry-run结果
  dryRunResult: any,
  
  // 其他元数据
  ...
}
```

### 3.2 决策日志存储

**存储位置**：
- 数据库表：`DecisionLog`（通过 `DecisionLogStorageService`）
- 服务文件：`src/trips/decision/services/decision-log-storage.service.ts`

**查询接口**：
- `GET /api/trips/:id/decision-log`: 获取决策日志
- `GET /api/trips/:id/evidence`: 获取证据列表

## 六、数据流程图

```
计划生成（TripDecisionEngineService.generatePlan）
    │
    ├─→ 生成初始计划（策略服务）
    │
    ├─→ 计算风险评分（DEMRiskScoringService.calculatePlanRiskScore）
    │   ├─→ 计算每日风险评分
    │   ├─→ 计算计划总风险评分
    │   └─→ 生成风险标志
    │
    ├─→ 生成证据链（DEMEvidenceChainService.generateEvidenceChain）
    │   ├─→ 生成计划级证据
    │   ├─→ 生成每日证据
    │   └─→ 生成时间槽证据
    │
    └─→ 生成DEM决策证据（DemDecisionEvidenceService.generateEvidencePipeline）
        ├─→ 生成路段证据
        ├─→ 检测连续疲劳
        ├─→ 计算走廊质量评分
        └─→ 生成可解释失败说明
            │
            └─→ 构建决策日志（DecisionRunLog）
                │
                └─→ 存储到数据库（DecisionLogStorageService）
                    │
                    └─→ 前端通过API获取展示
```

## 八、注意事项

1. **强制规则**：
   - 没有DEM证据的计划不允许finalize
   - Neptune不允许修复没有DEM证据的路段
   - Abu不允许忽略HARD violation

2. **性能考虑**：
   - 所有计算在计划生成阶段完成
   - 结果存储在决策日志中，前端直接查询
   - 避免在前端实时计算

3. **数据一致性**：
   - 证据、风险、决策数据都在同一个决策运行中生成
   - 通过 `DecisionRunLog` 关联所有数据
   - 查询时通过 `tripId` 和 `runId` 关联

4. **扩展性**：
   - 证据类型可扩展（TERRAIN、ENERGY、RISK等）
   - 风险标志可扩展
   - 决策原因代码可扩展
