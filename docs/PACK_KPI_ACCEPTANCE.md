# 国家 Pack KPI 验收文档

## 概述

P1.4: 国家 Pack KPI 验收

本文档说明如何验收国家 Pack 的 KPI，确保 RouteDirection 具有独特的个性、不同的约束组合，并且能够根据用户偏好产生不同的结果。

## KPI 定义

### 1. RouteDirection 独特性 KPI

**目标**：确保每个 RouteDirection 具有独特的个性

**指标**：
- **标签独特性得分**（0-100）：标签在其他路线方向中的出现频率
- **约束独特性得分**（0-100）：约束值在其他路线方向中的出现频率
- **风险画像独特性得分**（0-100）：风险特征在其他路线方向中的出现频率
- **总体独特性得分**（0-100）：加权平均（标签30% + 约束40% + 风险30%）

**验收标准**：
- 平均独特性得分 >= 60分
- 每个 RouteDirection 的总体独特性得分 >= 50分

**计算方法**：
- 对于每个特征（标签/约束/风险），计算在其他路线方向中的出现频率
- 如果出现频率 < 50%，则认为该特征独特
- 独特性得分 = (独特特征数 / 总特征数) * 100

### 2. 约束组合多样性 KPI

**目标**：确保不同的 RouteDirection 使用不同的约束组合

**指标**：
- **唯一约束组合数**：不同的约束组合数量
- **多样性得分**（0-100）：(唯一组合数 / 总路线方向数) * 100

**验收标准**：
- 至少 3 种不同的约束组合
- 多样性得分 >= 60分

**计算方法**：
- 提取每个 RouteDirection 的约束组合（hard + soft）
- 计算唯一约束组合数
- 多样性得分 = (唯一组合数 / 总路线方向数) * 100

### 3. 用户偏好差异化 KPI

**目标**：确保不同的用户偏好在不同国家/方向下产生不同的选择结果

**指标**：
- **测试场景数**：3个场景（轻松/中等/挑战）
- **产生差异化结果的场景数**：选择不同路线方向的场景数
- **差异化得分**（0-100）：(差异化场景数 / 总场景数) * 100

**验收标准**：
- 差异化得分 >= 70%
- 至少 2 个场景产生不同的选择结果

**测试场景**：
1. **轻松节奏，低风险偏好**：pace=relaxed, riskTolerance=low, intents={自然:0.7, 轻松:0.8}
2. **中等节奏，中等风险偏好**：pace=moderate, riskTolerance=medium, intents={自然:0.8, 摄影:0.7}
3. **挑战节奏，高风险偏好**：pace=intense, riskTolerance=high, intents={挑战:0.9, 徒步:0.8}

## 使用方法

### 1. 运行 KPI 验收

```bash
npx ts-node --project tsconfig.backend.json scripts/pack-kpi-acceptance.ts <countryCode>
```

**示例**：
```bash
# 验收冰岛的 Pack KPI
npx ts-node --project tsconfig.backend.json scripts/pack-kpi-acceptance.ts IS

# 验收西藏的 Pack KPI
npx ts-node --project tsconfig.backend.json scripts/pack-kpi-acceptance.ts CN_XZ
```

### 2. 查看验收报告

验收脚本会生成详细的验收报告，包括：

1. **总体验收状态**：PASS / FAIL / WARNING
2. **总体得分**：0-100分
3. **RouteDirection 独特性 KPI**：
   - 平均/最低/最高独特性得分
   - 各路线方向的独特性详情
   - 独特标签、约束、风险特征
4. **约束组合多样性 KPI**：
   - 多样性得分
   - 唯一约束组合数
   - 各约束组合的详情
5. **用户偏好差异化 KPI**：
   - 差异化得分
   - 各测试场景的结果
   - 是否产生差异化结果
6. **改进建议**：针对未通过的 KPI 提供改进建议

### 3. 验收流程

完整的 Pack 验收流程：

```bash
# 1. 生成 Pack
npx ts-node --project tsconfig.backend.json scripts/new-country-pack.ts IS Iceland

# 2. 编辑 Pack 文件
# 编辑 data/country-packs/country-pack-is.json

# 3. 校验 Pack（基础校验）
npx ts-node --project tsconfig.backend.json scripts/pack-validator.ts data/country-packs/country-pack-is.json

# 4. 导入到数据库
# 使用 seed 脚本或 API 导入

# 5. 运行 KPI 验收
npx ts-node --project tsconfig.backend.json scripts/pack-kpi-acceptance.ts IS
```

## 验收标准总结

### ✅ 通过标准

1. **RouteDirection 独特性**：
   - 平均独特性得分 >= 60分
   - 每个 RouteDirection 的总体独特性得分 >= 50分

2. **约束组合多样性**：
   - 至少 3 种不同的约束组合
   - 多样性得分 >= 60分

3. **用户偏好差异化**：
   - 差异化得分 >= 70%
   - 至少 2 个场景产生不同的选择结果

4. **总体得分**：
   - 总体得分 >= 70分

### ⚠️ 警告标准

如果满足以下条件，会显示警告但不会失败：

- 总体得分 >= 60分但 < 70分
- 部分 KPI 未通过但总体趋势良好

### ❌ 失败标准

如果满足以下任一条件，验收失败：

- 总体得分 < 60分
- RouteDirection 数量 < 3
- 平均独特性得分 < 50分
- 约束组合数 < 2
- 差异化得分 < 50%

## 改进建议

### 提高 RouteDirection 独特性

1. **增加独特标签**：
   - 为每个 RouteDirection 添加独特的标签
   - 避免所有 RouteDirection 使用相同的标签组合

2. **设置不同的约束值**：
   - 为不同的 RouteDirection 设置不同的 maxDailyAscentM、maxElevationM 等
   - 体现不同的难度和特点

3. **定义独特的风险画像**：
   - 为不同的 RouteDirection 设置不同的风险特征
   - 例如：高海拔路线设置 altitudeSickness=true，海岸线路线设置 ferryDependent=true

### 提高约束组合多样性

1. **创建不同的约束组合**：
   - 轻松路线：maxDailyAscentM=200, maxElevationM=1000
   - 中等路线：maxDailyAscentM=600, maxElevationM=3000
   - 挑战路线：maxDailyAscentM=1500, maxElevationM=6000, requiresPermit=true

2. **使用硬约束区分**：
   - 某些路线设置 requiresPermit=true
   - 某些路线设置 requiresGuide=true

### 提高用户偏好差异化

1. **优化标签匹配**：
   - 确保不同偏好的用户能够匹配到不同的标签
   - 例如：轻松偏好匹配"轻松"、"休闲"标签，挑战偏好匹配"挑战"、"徒步"标签

2. **调整约束权重**：
   - 确保不同 pace 的用户能够匹配到不同约束的路线
   - 例如：relaxed pace 匹配低约束路线，intense pace 匹配高约束路线

3. **完善季节性匹配**：
   - 确保不同月份的用户能够匹配到不同的路线
   - 例如：夏季匹配最佳月份路线，冬季匹配避免月份路线
