# 行程详情页信息架构分析与改进建议

## 📋 概述

本文档分析行程详情页的信息架构图，对比三人格定位文档，指出存在的问题，并提供改进建议。

**分析时间**: 2025-01-XX  
**文档版本**: 1.0

---

## 🔍 一、核心问题分析

### 1.1 数据硬编码问题

#### 问题描述

信息架构图中显示，多个视图组件使用了硬编码数据，而不是从后端API获取：

| 组件 | 硬编码数据 | 应该使用的API |
|------|-----------|--------------|
| **AutoView** | `overallMetrics` (safetyScore: 75, rhythmScore: 80等) | `GET /trips/:id/decision-log` + 计算 |
| **AutoView** | `关键问题列表` (硬编码) | `GET /trips/:id/persona-alerts` |
| **AbuView** | `gatingStatus`, `violations`, `riskMap` | `GET /trips/:id/decision-log?persona=ABU` |
| **DrDreView** | `metrics`, `metricsByItem` | `GET /trips/:id/metrics` (已获取但未使用) |
| **NeptuneView** | `repairs`, `alternatives` | `GET /trips/:id/decision-log?persona=NEPTUNE` |

#### 影响

1. **数据不准确**：硬编码数据无法反映真实的行程状态
2. **无法更新**：用户操作后，硬编码数据不会变化
3. **失去意义**：三人格的决策结果无法正确展示给用户

---

### 1.2 缺失的API对接

#### 问题描述

信息架构图中标注了多个"未对接的接口"，但实际上这些接口可能不需要单独实现，应该使用现有的接口：

| 标注的"未对接接口" | 实际应该使用 | 状态 |
|------------------|------------|------|
| `GET /trips/:id/risk-assessment` | `GET /trips/:id/decision-log?persona=ABU` | ✅ 已存在 |
| `GET /trips/:id/violations` | `GET /trips/:id/decision-log?persona=ABU&action=REJECT` | ✅ 已存在 |
| `GET /trips/:id/items/:itemId/risk` | `GET /trips/:id/decision-log` + 过滤 | ✅ 已存在 |
| `GET /trips/:id/repairs` | `GET /trips/:id/decision-log?persona=NEPTUNE&action=REPLACE` | ✅ 已存在 |
| `GET /trips/:id/items/:itemId/alternatives` | `GET /trips/:id/suggestions?scope=item&scopeId=:itemId` | ✅ 已存在 |
| `GET /trips/:id/overall-metrics` | 基于 `decision-log` + `metrics` 计算 | ⚠️ 需要计算 |

#### 结论

**不需要新增接口**，应该：
1. 使用现有的 `GET /trips/:id/decision-log` 接口，通过查询参数过滤
2. 使用现有的 `GET /trips/:id/persona-alerts` 接口
3. 使用现有的 `GET /trips/:id/suggestions` 接口
4. 在前端计算综合指标

### 1.3 数据流不匹配

#### 问题描述

信息架构图中的数据流与三人格定位文档不匹配：

**架构图显示**：
```
AutoView → 硬编码的 overallMetrics
AbuView → 硬编码的 gatingStatus, violations
DrDreView → 硬编码的 metrics
NeptuneView → 硬编码的 repairs
```

**应该的数据流**（根据三人格定位文档）：
```
决策日志 (DecisionLog) → 按 persona 过滤 → 展示在对应视图
人格提醒 (PersonaAlerts) → 按 persona 分类 → 展示在对应视图
证据链 (Evidence) → 关联到决策日志 → 展示在对应视图
```

#### 正确的数据流应该是

```
页面加载
  ↓
GET /trips/:id/decision-log (获取所有决策日志)
  ↓
按 persona 分组
  ├─ ABU 日志 → AbuView
  ├─ DR_DRE 日志 → DrDreView
  └─ NEPTUNE 日志 → NeptuneView
  ↓
GET /trips/:id/persona-alerts (获取人格提醒)
  ↓
按 persona 分组
  ├─ ABU 提醒 → AbuView
  ├─ DR_DRE 提醒 → DrDreView
  └─ NEPTUNE 提醒 → NeptuneView
  ↓
GET /trips/:id/evidence (获取证据)
  ↓
关联到决策日志
  └─ 在视图中展示证据详情
```

/**
 * 从决策日志中提取 Abu 相关数据
 */
function extractAbuData(
  decisionLogs: DecisionLogEntry[],
  personaAlerts: PersonaAlert[]
): AbuViewData {
  const abuLogs = decisionLogs.filter(log => log.persona === 'ABU');
  const abuAlerts = personaAlerts.filter(alert => alert.persona === 'ABU');
  
  // 计算 gatingStatus
  const hasReject = abuLogs.some(log => log.action === 'REJECT');
  const hasAllow = abuLogs.some(log => log.action === 'ALLOW');
  const gatingStatus = hasReject ? 'BLOCKED' : 
                      hasAllow ? 'PASSED' : 
                      abuAlerts.length > 0 ? 'WARN' : 'UNKNOWN';
  
  // 提取 violations
  const violations = abuLogs
    .filter(log => log.action === 'REJECT')
    .map(log => ({
      id: log.id,
      timestamp: log.timestamp,
      explanation: log.explanation,
      reasonCodes: log.reasonCodes,
      affectedDays: extractAffectedDaysFromLog(log),
      evidenceRefs: log.evidenceRefs || [],
    }));
  
  // 构建风险地图（关联到行程项）
  const riskMap = buildRiskMapFromLogs(abuLogs);
  
  return {
    gatingStatus,
    violations,
    riskMap,
    logs: abuLogs,
    alerts: abuAlerts,
  };
}

### 3.3 综合指标计算函数

```typescript
/**
 * 计算综合指标（用于 AutoView）
 */
function calculateOverallMetrics(
  decisionLogs: DecisionLogEntry[],
  personaAlerts: PersonaAlert[],
  suggestionStats: SuggestionStats
): OverallMetrics {
  // 1. 按人格分组日志
  const abuLogs = decisionLogs.filter(log => log.persona === 'ABU');
  const drDreLogs = decisionLogs.filter(log => log.persona === 'DR_DRE');
  const neptuneLogs = decisionLogs.filter(log => log.persona === 'NEPTUNE');
  
  // 2. 计算安全评分（0-100）
  const abuRejects = abuLogs.filter(log => log.action === 'REJECT').length;
  const abuWarnings = personaAlerts.filter(
    alert => alert.persona === 'ABU' && alert.severity === 'WARNING'
  ).length;
  const safetyScore = Math.max(0, 100 - (abuRejects * 20) - (abuWarnings * 10));
  
  // 3. 计算节奏评分（0-100）
  const drDreAdjusts = drDreLogs.filter(log => log.action === 'ADJUST').length;
  const drDreInfos = personaAlerts.filter(
    alert => alert.persona === 'DR_DRE' && alert.severity === 'INFO'
  ).length;
  const rhythmScore = Math.max(0, 100 - (drDreAdjusts * 15) - (drDreInfos * 5));
  
  // 4. 计算修复评分（0-100）
  const neptuneReplaces = neptuneLogs.filter(log => log.action === 'REPLACE').length;
  const neptuneSuggestions = suggestionStats.byPersona?.neptune || 0;
  const readinessScore = Math.max(0, 100 - (neptuneReplaces * 10) - (neptuneSuggestions * 3));
  
  return {
    safetyScore: Math.round(safetyScore),
    rhythmScore: Math.round(rhythmScore),
    readinessScore: Math.round(readinessScore),
    criticalIssues: personaAlerts.filter(a => a.severity === 'WARNING' && a.persona === 'ABU').length,
    warnings: personaAlerts.filter(a => a.severity === 'INFO').length,
    suggestions: suggestionStats.total || 0,
  };
}
```
