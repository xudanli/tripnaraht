## 📂 主要目录详解

### 1. `/src` - 源代码目录（核心业务逻辑）

这是 NestJS 后端应用的主要代码目录，采用模块化架构。

#### 1.1 `/src/app.module.ts`
- **作用**: NestJS 应用的根模块，注册所有功能模块
- **内容**: 导入所有子模块（PlacesModule, TripsModule, TransportModule 等）

#### 1.2 `/src/main.ts`
- **作用**: 应用入口文件，启动 NestJS 服务器
- **功能**: 
  - 配置全局验证管道
  - 启用 CORS
  - 配置 Swagger API 文档
  - 启动 HTTP 服务器（默认 3000 端口）

#### 1.3 `/src/app/` - Next.js 前端应用
- **作用**: Next.js 14 前端应用代码
- **文件**:
  - `*.tsx`: React 组件
  - `*.css`: 样式文件
  - `*.ico`: 图标文件

#### 2.1.1 `/src/trips/decision/` - 决策引擎模块（第一性原理架构）

**作用**: 世界级路线认知 Agent 的核心决策系统，基于第一性原理（物理现实、人体能力、路线哲学）进行决策。

**核心架构：三个"一等公民"模型**

1. **PhysicalRealityModel（物理现实模型）**
   - 文件: `models/physical-reality.model.ts`
   - 对应第一性原理：地形（DEM、高程、坡度）、路网（road/ferry/rail）、自然障碍、Hazard（雪崩、泥石流）、季节性 & 封路状态
   - 约束：没有 PhysicalRealityModel，就不允许生成"可执行计划"

2. **HumanCapabilityModel（人体能力模型）**
   - 文件: `models/human-capability.model.ts`
   - 对应第一性原理：单日可承受爬升、连续滚动爬升、最大坡度、高海拔适应度、风险承受度、节奏偏好
   - 约束：DecisionParams 是从这个模型投影出来的

3. **RoutePhilosophyModel（路线哲学模型）**
   - 文件: `models/route-philosophy.model.ts`
   - 对应第一性原理：不可背叛的哲学（philosophy invariants）vs 可调整的自由度
   - 约束：Neptune 只在 flexibleParts 动刀，不动 coreStatement 对应的结构

**三段式 WorldModelContext**
- 文件: `shared/world-model.types.ts`
- 结构：
  ```typescript
  {
    physical: PhysicalRealityModel;      // 地球那一坨
    human: HumanCapabilityModel;         // 人那一坨
    routeDirection: RouteDirectionWithPhilosophy; // 世界观那一坨
  }
  ```

**三人格决策策略（Strategy Pattern）**

1. **Abu Strategy（安全否决者）**
   - 文件: `strategies/abu-strategy.service.ts`
   - 职责：硬约束检查，安全把关
   - 第一性原理：只接受"物理现实 + 合规"的输入
   - 只读 `world.physical` 和 `complianceEvidence`，不读任何 tag/体验类字段
   - 检查：DEM 硬违规、道路状态、危险区域、渡轮状态、合规、气候季节性

2. **Dr.Dre Strategy（节奏修复者）**
   - 文件: `strategies/dr-dre-strategy.service.ts`
   - 职责：结构修复，节奏管理
   - 第一性原理：必须完全以 HumanCapabilityModel 驱动
   - PaceConstraints 100% 由 `world.human` + RD softConstraints 生成
   - 所有决策条件统一写成对 `fatigueIndex`、`rollingAscent3DaysM` 的判断

3. **Neptune Strategy（空间修复者）**
   - 文件: `strategies/neptune-strategy.service.ts`
   - 职责：空间替换，路线修复
   - 第一性原理：必须强依赖 RoutePhilosophy + PhysicalReality
   - 替换前检查：不会违反 `nonNegotiableRules`
   - 替换后检查：核心标签/体验仍然覆盖
   - 空间约束：所有替代点/替代段必须在 corridorGeom 缓冲范围内或 regions 指定的区域内

**决策流程：**
```
Abu → Dr.Dre → Neptune → Finalize
```

**相关文件**:
- `trip-decision-engine.service.ts`: 决策引擎主服务，集成三人格策略
- `services/strategy-orchestrator.service.ts`: 策略编排服务

## 🧠 第一性原理架构

TripNARA 采用**第一性原理架构**，所有决策基于三个不可违背的原理：

### 三个"一等公民"模型

1. **PhysicalRealityModel（物理现实模型）**
   - 地形（DEM、高程、坡度）
   - 路网（road/ferry/rail）
   - 自然障碍、Hazard（雪崩、泥石流）
   - 季节性 & 封路状态
   - **约束**: 没有 PhysicalRealityModel，不允许生成"可执行计划"

2. **HumanCapabilityModel（人体能力模型）**
   - 单日可承受爬升
   - 连续滚动爬升
   - 最大坡度、高海拔适应度
   - 风险承受度、节奏偏好
   - **约束**: DecisionParams 是从这个模型投影出来的

3. **RoutePhilosophyModel（路线哲学模型）**
   - 不可背叛的哲学（philosophy invariants）
   - 可调整的自由度
   - **约束**: Neptune 只在 flexibleParts 动刀，不动 coreStatement 对应的结构

### 三段式 WorldModelContext

```typescript
{
  physical: PhysicalRealityModel;      // 地球那一坨
  human: HumanCapabilityModel;         // 人那一坨
  routeDirection: RouteDirectionWithPhilosophy; // 世界观那一坨
}
```

### 三人格决策策略

**决策流程：** `Abu → Dr.Dre → Neptune → Finalize`

1. **Abu（安全否决者）**
   - 只接受"物理现实 + 合规"的输入
   - 检查：DEM 硬违规、道路状态、危险区域、合规

2. **Dr.Dre（节奏修复者）**
   - 完全以 HumanCapabilityModel 驱动
   - 功能：连续疲劳检测、日拆分、缓冲日插入

3. **Neptune（空间修复者）**
   - 强依赖 RoutePhilosophy + PhysicalReality
   - 功能：入口替换、POI 替换、路段绕行
   - 约束：不允许违反路线哲学

详细文档请参考：`docs/FIRST_PRINCIPLES_ARCHITECTURE.md`
