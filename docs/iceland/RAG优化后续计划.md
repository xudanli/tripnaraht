## 🎯 后续优化建议

### 短期优化（1-2周）

#### 1. 完善测试集数据 ⭐⭐

**目标**: 填充测试集的 groundTruthChunkIds，建立可用的评估基准

**工作内容**:
- 使用 `find-chunks` API 为每个测试用例找到相关 chunks
- 人工审核并确认 groundTruthChunkIds
- 扩展测试集到 20-50 个测试用例
- 覆盖不同场景（租车、F路、天气、景点等）

**预期收益**:
- 建立可用的质量评估基准
- 支持回归测试
- 量化检索质量改进

**实现方式**:
```bash
# 1. 使用 API 查找相关 chunks
GET /api/rag/evaluation/testset/find-chunks?query=冰岛租车保险

# 2. 更新测试集
PUT /api/rag/evaluation/testset
{
  "testCases": [
    {
      "id": "is-car-insurance-001",
      "query": "冰岛租车保险怎么选？",
      "groundTruthChunkIds": ["chunk-uuid-1", "chunk-uuid-2"]
    }
  ]
}

# 3. 运行评估
POST /api/rag/evaluation/testset/run
```

#### 2. 优化 Reranking 性能 ⭐⭐

**目标**: 使用 Cross-encoder 模型替代 LLM，提升重排序速度和成本

**当前问题**:
- LLM 重排序延迟高（~2-3秒）
- LLM 调用成本较高
- 需要降级策略

**优化方案**:
- 集成 Cross-encoder 模型（如 `bge-reranker-base`）
- 本地部署或使用 API（如 HuggingFace Inference API）
- 保留 LLM 作为可选的高级重排序

**预期收益**:
- 延迟降低 80%（从 2-3秒到 0.3-0.5秒）
- 成本降低 90%（从 LLM 调用到本地模型）
- 准确率保持或提升

**工作量**: 3-5天

#### 3. 上下文压缩 ⭐

**预期收益**:

- 成本降低 30-50%
- 延迟略有降低

**工作量**: 5-7天
