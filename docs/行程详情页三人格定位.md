# 行程详情页的三人格定位

## 概述

TripNARA 采用**三人格决策系统（Strategy Pattern）**，每个角色在行程规划中承担不同的职责。在行程详情页，用户可以看到这三个人格的决策过程和结果，理解系统是如何为他们的行程把关的。

---

## 一、三人格基本定位

### 1.1 Abu（安全否决者 / 安全官）

**核心定位**：
- **职责**：硬约束检查，安全把关
- **决策来源**：`PHYSICAL`（物理现实）
- **用户可见标题**：安全官（PHYSICAL）

**能力范围**：
- DEM 证据验证
- 硬违规检测（HARD violation）
- 合规检查（道路状态、封路、季节性关闭、危险区域、许可、向导、签证）
- 物理现实模型验证

**权限限制**：
- ✅ 只能 `ALLOW`（允许）
- ✅ 只能 `REJECT`（拒绝）
- ❌ **不可** `ADJUST`（调整）
- ❌ **不可** `REPLACE`（替换）

**不关心的事项**：
- 用户偏好（tags、preferences）
- 路线体验（好不好玩）
- 节奏偏好（快慢）

**第一性原理**：
> 只接受"物理现实 + 合规"的输入。只读 `world.physical` 和 `complianceEvidence`。

**在系统中的位置**：
```
Abu：能不能走（物理现实）
  ↓
Dr.Dre：这样走下去几天后会不会崩（人体能力）
  ↓
Neptune：世界变了还能不能保持路线精神（路线哲学）
```

### 1.2 Dr.Dre（节奏修复者 / 节奏官）

**核心定位**：
- **职责**：结构修复，节奏管理
- **决策来源**：`HUMAN`（人体能力）
- **用户可见标题**：节奏官（HUMAN）

**能力范围**：
- 连续疲劳检测（rolling window 3天）
- 日拆分（将高强度的一天拆分成两天）
- 缓冲日插入（在疲劳期插入休息日）
- 人体能力模型驱动的节奏调整

**权限限制**：
- ✅ 可以 `ALLOW`（允许）
- ✅ 可以 `ADJUST`（调整）
- ❌ **不可** `REPLACE`（替换）
- ❌ **不可** 突破 Abu 的硬约束
- ❌ **不可** 改变 RouteDirection（大方向与哲学）

**工作范围**：
- 只在"每天怎么排" / "是否插休息日"上动手脚
- 目标不是更轻松，而是"整体可持续"

**第一性原理**：
> 必须完全以 `HumanCapabilityModel` 驱动。所有决策条件统一写成对 `fatigueIndex`、`rollingAscent3DaysM` 的判断。

**在系统中的位置**：
```
Abu（通过后）
  ↓
Dr.Dre：这样走下去几天后会不会崩（人体能力）
  ↓
Neptune
```

### 1.3 Neptune（空间修复者 / 修复官）

**核心定位**：
- **职责**：空间替换，路线修复
- **决策来源**：`PHILOSOPHY` + `SPATIAL`（路线哲学 + 空间）
- **用户可见标题**：修复官（PHILOSOPHY + SPATIAL）

**能力范围**：
- 入口替换（替换不可达的路线入口）
- POI 替换（替换不可用的POI）
- 路段绕行（在走廊内替换局部路段）
- 空间问题检测（入口不可达、POI不可用、路段阻塞等）

**权限限制**：
- ✅ 可以 `ALLOW`（允许）
- ✅ 可以 `REPLACE`（替换）
- ❌ **不可** 忽略硬约束（Abu 的法律）
- ❌ **不可** 改变 RouteDirection 哲学
- ❌ **不可** 在没有 DEM 证据的地方修复

**约束条件**：
- **空间约束**：所有替代点/替代段必须在 `corridorGeom` 缓冲范围内或 `regions` 指定的区域内
- **哲学约束**：
  - 不允许删掉 `philosophy.mustVisitTags` 对应的体验
  - 不允许跨越 `nonNegotiableRules`
- **替换前检查**：不会违反 `nonNegotiableRules`
- **替换后检查**：核心标签/体验仍然覆盖

**不能做的事**：
- ❌ 不能把"冰岛高地 F 路探险"换成"环岛一号公路"
- ❌ 不能帮用户偷偷忽略封路 / 禁止入内
- ❌ 不能在没有 DEM / 无证据的地方瞎修

**第一性原理**：
> 必须强依赖 `RoutePhilosophy` + `PhysicalReality`。Neptune 是"路线哲学的守护者 + 空间补丁的作者"。

**在系统中的位置**：
```
Abu（通过后）
  ↓
Dr.Dre（通过后）
  ↓
Neptune：世界变了还能不能保持路线精神（路线哲学）
  ↓
Finalize
```

## 二、决策流程

### 2.1 执行顺序

```
Abu → Dr.Dre → Neptune → Finalize
```

**流程说明**：
1. **Abu 评估**：检查硬约束，如果拒绝则终止流程
2. **Dr.Dre 评估**：调整节奏，如果调整了计划则使用调整后的计划
3. **Neptune 评估**：替换不可用路段，如果替换了计划则使用替换后的计划
4. **Finalize**：最终确认，生成决策日志

### 2.2 决策结果类型

| 人格 | 可执行动作 | 说明 |
|------|-----------|------|
| Abu | ALLOW, REJECT | 只有通过/拒绝两种选择 |
| Dr.Dre | ALLOW, ADJUST | 可以通过或调整节奏 |
| Neptune | ALLOW, REPLACE | 可以通过或替换空间要素 |

## 三、在行程详情页的展示

### 3.1 决策日志展示

**接口**：`GET /api/trips/:id/decision-log`

**数据结构**：
```typescript
{
  logs: [
    {
      persona: 'ABU' | 'DR_DRE' | 'NEPTUNE',
      action: 'ALLOW' | 'REJECT' | 'ADJUST' | 'REPLACE',
      explanation: string,
      reasonCodes: string[],
      timestamp: string,
      decisionSource: 'PHYSICAL' | 'HUMAN' | 'PHILOSOPHY' | 'HEURISTIC',
    }
  ]
}
```

**展示内容**：
- 按时间顺序展示所有决策日志
- 每个人格的决策动作和解释
- 原因代码（用于分类和统计）

### 3.2 人格提醒（Persona Alerts）

**接口**：`GET /api/trips/:id/persona-alerts`

**数据结构**：
```typescript
{
  items: [
    {
      id: string,
      persona: 'ABU' | 'DR_DRE' | 'NEPTUNE',
      name: string,  // 'Abu' | 'Dr.Dre' | 'Neptune'
      title: string, // '安全官（PHYSICAL）' | '节奏官（HUMAN）' | '修复官（PHILOSOPHY + SPATIAL）'
      message: string,
      severity: 'SUCCESS' | 'INFO' | 'WARNING',
      createdAt: string,
      metadata: {
        decisionSource: string,
        action: string,
        reasonCodes: string[],
      },
    }
  ]
}
```

**严重程度映射**：
- `REJECT` → `WARNING`
- `ADJUST` → `INFO`
- `ALLOW` / `REPLACE` → `SUCCESS`

### 3.3 证据链中的展示

在证据链（Evidence Chain）中，三人格的决策会体现在：

1. **计划级证据**：
   - Abu 的安全检查结果
   - 硬约束违反情况

2. **每日证据**：
   - Dr.Dre 的节奏调整（如插入休息日）
   - Neptune 的空间替换（如POI替换）

3. **决策解释**：
   - 每个人格的决策原因和解释

## 四、用户可见的解释语言风格

### 4.1 三人格的风格定义

**代码位置**：`src/trips/decision/interfaces/decision-log-enhanced.interface.ts`

```typescript
PERSONA_LOG_STYLES = {
  ABU: {
    keywords: ['冷静', '法律化', '不可谈判'],
    userExplanationTemplate: '我们没有选择这条路线，因为在 {affectedDays} 会出现 {reason}，这在当前季节和你的节奏偏好下存在明显风险。我们不会赌这件事。',
  },
  DR_DRE: {
    keywords: ['工程感', '结构修复'],
    userExplanationTemplate: '这条路线是可行的，但原本的节奏会让你在 {affectedPeriod} 明显疲劳。我们已经帮你把 {adjustment}，让体验更稳定。',
  },
  NEPTUNE: {
    keywords: ['空间', '连续性', '体验'],
    userExplanationTemplate: '路线本身没有问题，只是 {originalPlan} 在你到达时不可用。我们为你换了一个 {replacement}，你走的仍然是同一条路线。',
  },
}
```

### 4.2 解释语言示例

#### Abu 的拒绝解释

**模板**：
> 我们没有选择这条路线，因为在 {affectedDays} 会出现 {reason}，这在当前季节和你的节奏偏好下存在明显风险。我们不会赌这件事。

**示例**：
> 我们没有选择这条路线，因为在第 4、5、6 天会出现连续高强度爬升、高海拔风险，这在当前季节和你的节奏偏好下存在明显风险。我们不会赌这件事。

#### Dr.Dre 的调整解释

**模板**：
> 这条路线是可行的，但原本的节奏会让你在 {affectedPeriod} 明显疲劳。我们已经帮你把 {adjustment}，让体验更稳定。

**示例**：
> 这条路线是可行的，但原本的节奏会让你在中段明显疲劳。我们已经帮你把关键一天拆开，并插入了一个缓冲日，让体验更稳定。

#### Neptune 的替换解释

**模板**：
> 路线本身没有问题，只是 {originalPlan} 在你到达时不可用。我们为你换了一个 {replacement}，你走的仍然是同一条路线。

**示例**：
> 路线本身没有问题，只是原计划的入口在你到达时不可用。我们为你换了一个附近的入口，你走的仍然是同一条路线。

## 六、设计原则

### 6.1 责任分离

- **Abu**：只负责物理现实和安全，不关心用户体验
- **Dr.Dre**：只负责节奏和结构，不改变路线方向
- **Neptune**：只负责空间替换，保持路线哲学

### 6.2 不可越权

- 每个人格都有明确的权限边界
- 不能做超出自己职责范围的决策
- 遵循"最小权限原则"

### 6.3 可解释性

- 每个决策都有明确的解释
- 用户可以看到谁做了什么决定，为什么
- 决策过程完全透明

### 6.4 第一性原理

- 每个人格的决策都基于第一性原理
- 不依赖魔法参数或经验值
- 基于数据和模型驱动

## 八、注意事项

1. **决策顺序不可改变**：必须按照 Abu → Dr.Dre → Neptune 的顺序执行
2. **Abu 的拒绝是最终决定**：如果 Abu 拒绝，流程立即终止
3. **每个人格的权限边界**：严格遵守权限限制，不能越权
4. **解释语言的一致性**：使用定义好的模板，保持风格一致
5. **决策日志的完整性**：所有决策都必须记录到决策日志中

---

## 九、总结

三人格系统是 TripNARA 的核心设计，它：

1. **明确职责分工**：每个人格专注于自己的领域
2. **保证安全性**：Abu 作为第一道防线，确保物理现实安全
3. **优化体验**：Dr.Dre 优化节奏，Neptune 修复空间问题
4. **可解释性**：用户可以看到完整的决策过程和原因
5. **可扩展性**：每个人格可以独立优化和扩展

在行程详情页，用户可以通过决策日志、人格提醒和证据链，全面了解系统是如何为他们的行程把关和优化的。
