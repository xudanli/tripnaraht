# 数据库数据核对清单

本文档列出项目数据库中需要核对的关键数据项，确保底层数据的正确性和完整性。

## 一、核心业务数据

### 1.1 RouteDirection（路线方向）表

**必需字段完整性检查：**
- [ ] `uuid` 字段唯一性：检查是否有重复的 uuid
- [ ] `countryCode` 字段：所有记录必须有有效的国家代码（ISO 2字母代码）
- [ ] `name` 和 `nameCN` 字段：所有记录必须有名称和中文名称
- [ ] `tags` 数组：每条路线至少有一个标签

**业务逻辑完整性检查：**
- [ ] `regions` 数组：每条路线至少定义一个区域
- [ ] `entryHubs` 数组：每条路线至少定义一个入口枢纽
- [ ] `corridorGeom` 地理数据：验证地理走廊几何数据的有效性（WKT格式）
- [ ] `seasonality` JSON：验证最佳月份（bestMonths）和避免月份（avoidMonths）格式
- [ ] `constraints` JSON：验证硬约束（hard）和软约束（soft）结构
  - [ ] 硬约束字段：maxDailyRapidAscentM, maxSlopePct, rapidAscentForbidden, requiresPermit, requiresGuide
  - [ ] 软约束字段：maxDailyAscentM, maxElevationM, bufferTimeMin
- [ ] `riskProfile` JSON：验证风险画像数据完整性
- [ ] `signaturePois` JSON：验证签名POI数据
  - [ ] 至少定义 `types` 数组
  - [ ] 如有 `examples`，验证POI UUID是否存在于 poi_canonical 表
- [ ] `itinerarySkeleton` JSON：验证行程骨架数据结构
- [ ] `isActive` 字段：验证状态标记（true/false）
- [ ] `status` 字段：验证状态值（active/draft/archived等）
- [ ] `version` 字段：如有版本号，验证格式
- [ ] `rolloutPercent` 字段：验证灰度发布百分比（0-100）
- [ ] `updatedAt` 字段：确保比 `createdAt` 晚或相等

**外键关系检查：**
- [ ] 检查 RouteTemplate 表中的 `routeDirectionId` 是否都有对应的 RouteDirection
- [ ] 检查 RouteDirectionHealth 表中的 `routeDirectionId` 是否都有对应的 RouteDirection
- [ ] 检查 RouteDirectionDecision 表中的 `selectedRouteDirectionId` 和 `rejectedRouteDirectionIds` 是否有效

**空间数据检查：**
- [ ] `corridorGeom` 使用 PostGIS geography 类型，验证坐标系统（4326）
- [ ] 验证地理走廊是否与 `countryCode` 匹配
- [ ] 验证地理走廊是否与 `regions` 数据一致

**索引检查：**
- [ ] `countryCode` 索引是否存在
- [ ] `countryCode, isActive` 复合索引是否存在
- [ ] `tags` GIN 索引是否存在
- [ ] `status` 索引是否存在
